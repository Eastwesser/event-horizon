# Финальные результаты нагрузочного тестирования — ПОЛНЫЙ ОТЧЁТ

**Дата:** 11 мая 2026  
**Сервер:** 1 хост (Arch Linux), 9.6GB RAM  
**Цель:** Полная оценка ёмкости системы

## Результаты

| Тест | Нагрузка | Результат | Память |
|------|----------|-----------|--------|
| Чистый HTTP | 4000 users, 40k requests | ✅ 0 ошибок, 222-335ms | ~200MB |
| Чистый WebSocket | 6000 connections | ✅ 0 ошибок | 74MB |
| Чистый WebSocket | 8000 connections | ✅ 0 ошибок | 107MB |
| Чистый WebSocket | 10000 connections | ✅ 0 ошибок | 116MB |
| Смешанный | 6000 WS + 4000 HTTP | ✅ 0 ошибок (1-2 прогона) | ~300MB |
| Смешанный | 6000 WS + 4000 HTTP | ❌ таймауты (3+ прогона) | ~350MB |

## Максимальная устойчивая нагрузка

- **Долговременная:** 4000 WS + 4000 RPS HTTP
- **Пиковая (кратковременная):** 6000 WS + 4000 RPS HTTP
- **WebSocket только:** 10000+ соединений

## Узкие места

1. TCP TIME_WAIT при повторных запусках
2. Фрагментация памяти после длительной нагрузки
3. CPU при комбинированной нагрузке

## Что сделали правильно

- Graceful shutdown
- Batch ack в NATS
- Кеширование в Gateway
- Раздельные БД
