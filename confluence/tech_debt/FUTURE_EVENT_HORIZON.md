## Приоритет 1: i18n

**Цель:** дать пользователям выбор языка (Русский, English, Deutsch, Español) и сохранять его на всю сессию.

**Почему сейчас:** текущая аудитория — русскоязычная, но ты хочешь показать проект немецкому другу и потенциально расширяться. i18n — самое дешёвое улучшение с максимальным охватом.

### Что нужно сделать

1. **Инфраструктура**
   - Установить `i18next`, `react-i18next`, `i18next-browser-languagedetector`.
   - Создать `src/i18n/index.ts` с конфигом.
   - Обернуть `<App />` в `I18nextProvider` в `main.tsx`.
   - Хранить выбранный язык в `localStorage` (`eh_lang`).

2. **Файлы переводов**
   - `src/i18n/locales/ru.json` — базовый.
   - `src/i18n/locales/en.json`.
   - `src/i18n/locales/de.json`.
   - `src/i18n/locales/es.json`.

3. **UI**
   - Иконка флага рядом с бургером в `AppNavbar.tsx`.
   - Dropdown: `Русский` / `English` / `Deutsch` / `Español`.
   - При клике — `i18n.changeLanguage(lang)`.

4. **Переводы**
   - **Первая волна:** навигация (`AppNavbar`), auth (login/register), главная (`Home`), список игр, настройки профиля.
   - **Вторая волна:** игры (названия, описания, How-to-play).
   - **Третья волна:** shop, inventory, leaderboard.
   - **Четвёртая волна:** admin, analytics, authors.

5. **Тестирование**
   - Пройти сценарий регистрации + игры на английском и немецком.

### Что **не** трогаем

- Backend-строки (gRPC-ошибки) — оставляем на английском.
- Email/уведомления — не переводим (только in-app).
- Сложные форматы (валюта, даты) — используем `Intl` из коробки.

### Ожидаемый результат

Пользователь из любой страны может зайти, выбрать язык, играть и понимать интерфейс.

## Приоритет 2: Tech Debt

**Цель:** закрыть проблемы, найденные при разборе паттернов в `EVENT_HORIZON_PATTERNS_15.10.2026.md`.

Все проблемы разбиты по **сервисам** и **критичности**. Подробные описания — в разделе «Потенциальные улучшения / предпродовый релиз» каталога паттернов.

### Критичные (Pre-Prod)

| # | Сервис | Проблема | Решение |
|---|--------|----------|---------|
| 1 | fulfillment | Заглушка `time.After(10s)` вместо WMS | Заменить на реальный API |
| 2 | fulfillment | Нет Outbox — событие потеряется при падении | Transactional Outbox |
| 3 | billing | `RewardConsumer` использует `time.Now()` для `reference_id` | Использовать `event.ReferenceID` |
| 4 | gateway | Два Hub (`app/gateway.go` и `websocket/hub.go`) | Унифицировать |
| 5 | gateway | `runGateway` — God Function (>1000 строк) | Разбить на модули |
| 6 | balancer | Пустые пакеты `backend/`, `proxy/` | Удалить или наполнить |
| 7 | balancer | `/ready` не проверяет бэкенды | Реальная проверка |
| 8 | balancer | Нет health checks бэкендов | Периодический ping |
| 9 | notification | Poison message при unmarshal error | Ack в этом случае |
| 10 | mcp | SQL sandbox через string matching | Read-only роль + prepared statements |
| 11 | mcp | Утечка внутренних деталей через `err.Error()` | Санитизировать |
| 12 | shop | `cancelPurchase` — двойное начисление при повторной отмене | Idempotency Key |

### Средней важности

| # | Сервис | Проблема |
|---|--------|----------|
| 13 | shop | `kafkaProd` создаётся, но не используется |
| 14 | shop | `paymentClient` может быть nil — нет метрики |
| 15 | analytics | `fmt.Sprintf` для db name — SQL injection при user input |
| 16 | inventory | Два драйвера (Postgres + MongoDB) — двойная поддержка |
| 17 | game | `SubmitScore` — god-function на 8 игр |
| 18 | authors | `RevertApplication` удаляет `authors` — FK могут упасть |
| 19 | leaderboard | `RestoreFromPostgres` при старте — если БД упала, LB пустой |
| 20 | billing | `GetBalance` возвращает `-1` при cache miss — можно спутать |

### Мелкие

| # | Сервис | Проблема |
|---|--------|----------|
| 21 | gateway | `log.Printf` везде — нет структурированного логирования |
| 22 | balancer | `log.Printf` в hot path |
| 23 | fulfillment | `newUUID` (crypto/rand) vs `uuid.NewString()` — несогласованность |
| 24 | mcp | `mcp.NewToolResultError(err.Error())` — утечка деталей |

### Что **не** улучшать

- Saga в `shop` — работает корректно.
- Circuit Breaker в `gateway` — минимальный, но работает.
- Least Connections в `balancer` — правильный алгоритм.
- Double-Entry Ledger в `billing` — фундамент.

## Приоритет 3: Игровая оптимизация

**Цель:** сделать игры **плавнее**, **честнее**, **интереснее**. Бусты — не «ещё одна галочка», а осознанный выбор.

### Что улучшить

1. **Производительность игр**
   - Memonia: 30 карточек — использовать `React.memo`, `useCallback`.
   - Flappy: 60 FPS стабильно, `requestAnimationFrame` уже есть.
   - Gears: физика через `requestAnimationFrame`, проверить steady state.
   - Hanoi: анимация через `transform`, не через `top/left`.

2. **Унификация интерфейса**
   - Все игры — единый `GameShell`.
   - Кнопка «На главную» — слева.
   - Буст — в `controls`, последним.
   - «Как играть» — `GameHelp` с per-game текстами.

3. **Бусты**
   - Каждый буст — с понятным объяснением (сделано в `BoostCheckbox`).
   - Проверить: для каждой игры есть буст-эффект.
   - Дополнить: `companion` (нет буста, и это ок).

4. **Лидерборд**
   - Кнопка «Топ-10» в каждой игре (сделано).
   - Отображение ранга игрока после submit.
   - Единый формат очков.

5. **Игровые механики**
   - Memonia: добавить level-up механики.
   - Gears: добавить визуальные подсказки.
   - Hanoi: улучшить анимацию перекладывания.
   - 2048: добавить «undo» после буста (сделано).

6. **Новые игры (возможно)**
   - Если будет время — добавить одну игру для разнообразия.

### Что **не** трогаем

- Формулы очков (уже сбалансированы).
- Стоимость бустов (10 ламп везде).
- Награды за игру (лампы + билетики).

## Приоритет 5: Observability и безопасность

**Цель:** довести систему до **зрелого уровня** по мониторингу и защите.

### Observability

1. **Metrics**
   - Prometheus есть, но не везде.
   - Grafana dashboards (нет).
   - Alerting rules (нет).

2. **Tracing**
   - OTel / Jaeger есть в 7 сервисах.
   - Добавить в остальные 10.
   - Sampling policy (нет).

3. **Logging**
   - Структурированное логирование (`slog`) — есть в 12 сервисах.
   - Добавить в `gateway` (там `log.Printf`).
   - Log aggregation (Loki) — нет.

4. **SLO / SLA**
   - Определить SLO: 99.9% uptime, p99 < 500ms.
   - Мониторить error budget.
   - Incident response (нет).

### Безопасность

1. **Auth**
   - JWT access + refresh — есть.
   - Session store в Redis — есть.
   - MFA (нет).

2. **API**
   - Rate limiting — есть в `gateway`.
   - WAF (нет).
   - DDoS protection (нет).

3. **Data**
   - Encryption at rest (нет).
   - Encryption in transit (TLS) — не везде.
   - Secrets management (Vault) — нет.

4. **Audit**
   - Audit log (нет).
   - Access log (есть в `gateway`).
   - PII detection (нет).

5. **Testing**
   - Penetration testing (нет).
   - Fuzzing (нет).
   - SAST / DAST (нет).

### Что **не** делаем

- Свой crypto — используем библиотеки.
- Свой auth — используем JWT + Redis.
