Inventory — полный разбор для собеса
Разбираю так же, как предыдущие. Всё, что известно по services/inventory из твоих файлов. 28 паттернов — второй по богатству после Shop.

1. Одна фраза (elevator pitch)
Inventory — каталог автора: карточки мерча, атрибуты, склад. Два драйвера БД: Postgres (основной, source of truth) и Mongo (experimental, гибкие атрибуты). Через Strategy выбирается драйвер по env INVENTORY_DRIVER. Сверху — Decorator CachedRepository: Cache-Aside в Redis. Каждое создание карточки — outbox inventory.item.created в той же транзакции, Shop его потребляет и создаёт строку каталога. Outbox через интерфейс + Type Assertion — необычный кейс. Изменения в Mongo ловятся через Change Streams (CDC). 28 паттернов.

4. Как работает (по шагам)
CreateItem (создание карточки)
Gateway → gRPC CreateItem. RequireRole(author|admin) на Gateway.

Inventory gRPC interceptor проверяет x-user-role из metadata.

Strategy: выбирается драйвер по env INVENTORY_DRIVER (postgres или mongo).

Postgres driver (основной):

INSERT items с version = 1

INSERT outbox(inventory.item.created) — в той же транзакции

commit

Cache Invalidation: redisRepo.DeleteList(ctx) — сброс кэша списка.

Outbox worker публикует inventory.item.created в NATS.

Shop durable consumer shop-inventory-sync создаёт строку shop.items — карточка появляется в витрине.

Необычный кейс: Outbox через интерфейс + Type Assertion. Это значит, что outbox-строка пишется через интерфейс OutboxRepository, а драйвер проверяет, поддерживает ли он транзакции, через type assertion. Это работает, но хрупко — при добавлении нового драйвера можно забыть реализовать интерфейс.

GetItem / ListItems (чтение)
Gateway → gRPC GetItem / ListItems.

Decorator CachedRepository: Cache-Aside в Redis.

GetItem: ключ item:{id}, промах → PG/Mongo, запись в Redis.

ListItems: ключ list:{hash(filters)}, промах → PG/Mongo, запись в Redis.

Инвалидация после мутации: DeleteItem / DeleteList.

UpdateItem
Gateway → gRPC UpdateItem. RequireRole(author|admin).

Optimistic Lock: UPDATE … WHERE id=$1 AND version=$2. 0 rows → ErrVersionConflict.

Gateway мапит ErrVersionConflict в 409 Conflict.

INSERT outbox(inventory.item.updated) в той же транзакции.

Cache Invalidation.

Reserve / SoftDelete / Restore
Reserve: UPDATE stock = stock - $1 WHERE id=$2 AND stock >= $1. Атомарно.

SoftDelete: UPDATE deleted_at = now() WHERE id=$1. Не удаляет физически.

Restore: UPDATE deleted_at = NULL WHERE id=$1.

Все три — с optimistic lock на version.

Mongo driver (experimental)
INVENTORY_DRIVER=mongo — Strategy выбирает Mongo.

MongoDB Transaction + Aggregation + $lookup: для чтения карточки с атрибутами — один aggregation-запрос вместо нескольких.

Change Streams (CDC): изменения в Mongo ловятся через change streams, а не polling.

Outbox через type assertion: если драйвер поддерживает транзакции — outbox пишется в той же транзакции.

Фильтры (ListItems)
Gateway → gRPC ListItems с фильтрами.

Filter Builder / Parameterized Query: toPostgresFilter собирает SQL через fmt.Sprintf для имён колонок, но значения идут плейсхолдерами $1, $2. Это защита от SQL injection.

Pagination / Clamp: лимит на размер страницы.

Cache-Aside: ключ list:{hash(filters)}.

Важно: в каталоге паттернов отмечено: «toPostgresFilter собирает SQL через fmt.Sprintf — если появятся новые фильтры, может утечь. Уже защищено через $1, $2». Честно: имена колонок зашиты, значения — плейсхолдерами.

Необычные кейсы (стоит рассказать)
1. Strategy: два драйвера БД.
INVENTORY_DRIVER=postgres или mongo. Strategy выбирает драйвер. Интерфейс ItemRepository — общий, реализации разные. На собесе честно: «Mongo — experimental, в текущем compose postgres. Но код драйвера есть».

2. Decorator CachedRepository — самый чистый Cache-Aside.
Поверх ItemRepository — CachedRepository, который сначала смотрит в Redis, промах → делегирует в PG/Mongo, запись в Redis. Repository не знает про кэш. Это классический Decorator.

3. Change Streams (CDC) для Mongo.
Вместо polling — Mongo change streams. Изменения в коллекции ловятся как поток событий. Это Mongo-специфично, для Postgres — Debezium (как в Roolz).

4. Outbox через интерфейс + Type Assertion.
Outbox-строка пишется через интерфейс OutboxRepository. Драйвер проверяет, поддерживает ли он транзакции, через type assertion. Работает, но хрупко: при добавлении нового драйвера можно забыть реализовать интерфейс. На собесе честно: «Знаю, что хрупко, но работает».

5. RBAC через интерсепторы.
Inventory gRPC interceptor читает x-user-role из metadata. Gateway кладёт роль туда после ValidateToken. Без роли на мутирующих RPC — PermissionDenied. Это защита на уровне сервиса, не только Gateway.

6. Filter Builder с fmt.Sprintf для имён колонок.
toPostgresFilter собирает SQL через fmt.Sprintf для имён колонок, но значения идут плейсхолдерами $1, $2. Имена колонок зашиты в код, не приходят от клиента. Это защита от SQL injection. В каталоге отмечено: «если появятся новые фильтры, может утечь» — честно, знаю.

7. Soft Delete / Restore.
deleted_at вместо физического удаления. Restore возвращает. Это паттерн для каталога: карточка может быть временно скрыта, но не удалена.

9. Что спросят на собесе (готовые ответы)
«Почему два драйвера БД?»
Честно: Mongo — experimental. Гибкие атрибуты карточек (у разных категорий разные поля) — Mongo удобнее. Но в текущем compose INVENTORY_DRIVER=postgres — Postgres основной. Strategy выбирает драйвер по env. В техдолге: «Определиться с одним». Сейчас — оба.

«Почему Decorator для кэша?»
CachedRepository поверх ItemRepository. Repository не знает про кэш — Decorator сначала смотрит в Redis, промах → делегирует в PG/Mongo, запись в Redis. Это классический Cache-Aside через Decorator. Самый чистый вариант — не размазывать кэш по сервису.

«Что такое Change Streams?»
Mongo-специфичный CDC: изменения в коллекции ловятся как поток событий, а не polling. Для Postgres — Debezium (как в Roolz). Здесь — Mongo change streams. Если драйвер Postgres — CDC нет, outbox пишется в той же транзакции.

«Что за Outbox через интерфейс + Type Assertion?»
Outbox-строка пишется через интерфейс OutboxRepository. Драйвер проверяет, поддерживает ли он транзакции, через type assertion. Работает, но хрупко: при добавлении нового драйвера можно забыть реализовать интерфейс. Честно: знаю, что хрупко.

«Что такое RBAC через интерсепторы?»
Inventory gRPC interceptor читает x-user-role из metadata. Gateway кладёт роль туда после ValidateToken. Без роли на мутирующих RPC — PermissionDenied (403 на Gateway). Это защита на уровне сервиса, не только Gateway.

«Почему toPostgresFilter через fmt.Sprintf — не SQL injection?»
fmt.Sprintf для имён колонок, но значения идут плейсхолдерами $1, $2. Имена колонок зашиты в код, не приходят от клиента. Это защита. В каталоге отмечено: «если появятся новые фильтры, может утечь» — честно, знаю.

«Почему Soft Delete?»
deleted_at вместо физического удаления. Restore возвращает. Карточка может быть временно скрыта, но не удалена. Это паттерн для каталога: автор скрыл товар, но история осталась.

«Почему Optimistic Lock, а не Pessimistic?»
version на items. Авторы редактируют карточки редко, конфликты — редкость. Optimistic Lock дешевле: UPDATE … WHERE version=$2, 0 rows → ErrVersionConflict → 409. Pessimistic Lock (FOR UPDATE) держал бы строку на всё время редактирования — плохо для UX.

«Что если два автора редактируют одновременно?»
Optimistic Lock: первый UPDATE с version=1 проходит, version=2. Второй UPDATE с version=1 — 0 rows → ErrVersionConflict → 409 Conflict. Клиент перечитывает и повторяет. Это стандартный optimistic lock.

«Почему мерч-гейт в Shop, а не в Inventory?»
Inventory — каталог автора. Shop — витрина и покупка. Мерч-гейт (CanPurchaseMerch) — бизнес-правило покупки, поэтому в Shop. Inventory не знает про подписки.

«Как тестируешь Inventory?»
Unit — мок репозитория. Integration — testcontainers (реальный PG). Mongo test — //go:build integration (build tag). k6 CORE — browse.js (20 VU) читает каталог. Legacy 500 VU login blast — не pass/fail.

«Что улучшил бы?»
Определиться с одним драйвером БД (Postgres или Mongo)

toPostgresFilter — переписать без fmt.Sprintf для имён колонок (даже если сейчас безопасно)

Outbox через type assertion — сделать явный интерфейс TransactionalRepository

Алерт на inventory_version_conflicts_total резко растёт

11. Что важно не перепутать
Inventory — не Shop. /api/v1/inventory/items — каталог автора. /api/v1/shop/inventory — купленные скины.

INVENTORY_DRIVER=postgres в текущем compose. Mongo — experimental.

Decorator CachedRepository — самый чистый Cache-Aside.

Change Streams — Mongo-специфично.

Outbox через type assertion — хрупко, знаю.

RBAC через интерсепторы — x-user-role из metadata.

Soft Delete / Restore — deleted_at, не физическое удаление.

Optimistic Lock — version, 409 на конфликт.
