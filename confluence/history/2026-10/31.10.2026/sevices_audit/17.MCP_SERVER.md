1. Одна фраза (elevator pitch)
MCP — stdio-сервер для Cursor / Claude Desktop, не HTTP-ручка сайта. Шесть tools: search_prydwen (RAG), nats_list_streams, nats_list_consumers, postgres_query (SELECT-only), redis_get, redis_keys. MCP Server + Tool Registration + stdio Transport. SQL Sandbox ValidateSelect — string matching, легко обходится (техдолг). Offline RAG (TF-IDF) без embedding API. Graceful Degradation per-tool — один tool упал, остальные работают. В игровом стеке make deploy не участвует. 15 паттернов.

только SELECT

9. Что спросят на собесе (готовые ответы)
«Что такое MCP?»
Model Context Protocol — протокол для AI-агентов (Cursor, Claude Desktop). MCP-сервер отдаёт tools, AI их вызывает. Это не HTTP-API для людей, а tool-API для AI. В EH — stdio-сервер с 6 tools.

«Почему stdio, а не HTTP?»
Cursor / Claude Desktop запускают MCP как дочерний процесс, общаются через stdin/stdout. Нет HTTP, нет порта. Плюс: не в сети, не нужен auth. Минус: не масштабируется на несколько клиентов.

«Какие tools?»
6 tools: search_prydwen (RAG), nats_list_streams, nats_list_consumers, postgres_query (SELECT-only), redis_get, redis_keys. Все — только чтение.

«Что такое SQL Sandbox?»
ValidateSelect — string matching: только SELECT, запрет UNION / EXCEPT / INTERSECT, лимит строк. Легко обходится (техдолг). Решение: read-only роль в Postgres + pgx prepared statements. Честно: знаю, что string matching — не безопасно.

«Что такое Offline RAG (TF-IDF)?»
search_prydwen — TF-IDF по markdown-файлам Prydwen. Не embedding API, не Qdrant. Offline, дешево. Минус: хуже качество. В техдолге: «Опционально: добавить embedding fallback (OpenAI)».

«Что такое Graceful Degradation per-tool?»
Если один tool упал (например, NATS недоступен) — остальные работают. Не «весь MCP упал», а «этот tool вернул ошибку». Это защита от «один tool упал — весь MCP упал».

«Почему MCP не в player path?»
В MIRO_STICKERS_PASTE.md: «MCP — stdio (not /api/v1), tools: ... · not in player path». То есть MCP не участвует в обработке игровых запросов. Это dev-tool для Cursor, не для игроков.

«Почему MCP не в compose?»
В README.md: «MCP — stdio-процесс для Cursor, не ручка сайта». MCP не в docker-compose.cluster.yml, не в make deploy. Запускается Cursor / Claude Desktop как дочерний процесс.

«Почему mcp.NewToolResultError(err.Error()) — проблема?»
Утечка внутренних деталей. Если tool упал с ошибкой БД, клиент увидит DSN, SQL, etc. Техдолг: «Санитизировать сообщения». Честно: знаю.

«Почему в сеть нельзя?»
В FINISHERS.md: «В сеть его выпускать нельзя: DSN, который ему дали, он читает целиком». То есть MCP имеет полный доступ к Postgres (read-only, но DSN). Если выпустить в сеть — можно прочитать всё. Поэтому только stdio, только локально.

«Как тестируешь MCP?»
Unit — мок tools, SQL Sandbox (проверка ValidateSelect), TF-IDF (проверка поиска). Integration — testcontainers (реальный PG/Redis/NATS). stdio — тест через JSON-RPC.

«Что улучшил бы?»
SQL Sandbox: read-only роль в Postgres + pgx prepared statements (сейчас string matching)

Санитизация ошибок (сейчас err.Error())

Embedding fallback для RAG (сейчас только TF-IDF)

Не выпускать в сеть (сейчас stdio, но если понадобится HTTP — нужен auth)
