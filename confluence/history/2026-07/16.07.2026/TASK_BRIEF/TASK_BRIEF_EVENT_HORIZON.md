❌ РЕШЕНИЕ: НЕ НУЖЕН СЕЙЧАС
Почему нет:
1. Соло-разработка — оверхед MCP не оправдан
MCP требует поддержки: документация, версионирование, совместимость

Это отнимает время от основной разработки (Payment, Notification)

Сейчас проще использовать существующие инструменты

2. Активная фаза разработки — API ещё меняются
Shop только что доделан

Payment и Notification в планах

Любые изменения API потребуют синхронизации с MCP

Сейчас нет стабильного API для интеграции

3. Существующая инфраструктура уже даёт всё нужное
NATS — для событийной шины (уже есть)

Prometheus + Grafana — для метрик (уже есть)

HTTP API — для пользовательских данных (уже есть)

WebSocket — для real-time (уже есть)

4. Планы на будущее
OpenAPI / Swagger — это даст документацию для AI

Логи + Jaeger — для отладки

k3s + Observability — когда дойдём до масштабирования

🔧 АЛЬТЕРНАТИВА (сейчас)
"Manual AI Integration" — используй что уже есть:
1. Метрики → Prometheus API
bash
curl -s http://localhost:9090/api/v1/query?query=up
2. События → NATS CLI
bash
# Подписаться на события
nats sub "score.updated" --server localhost:4222

# Опубликовать событие
nats pub "shop.purchased" '{"user_id":"123","item_id":"456"}'
3. Пользовательские данные → HTTP API
bash
TOKEN=$(curl -s -X POST http://localhost:8079/api/auth/login -H "Content-Type: application/json" -d '{"email":"user@example.com","password":"pass"}' | jq -r '.access_token')
curl -s -X GET "http://localhost:8079/api/billing/balance/all" -H "Authorization: Bearer $TOKEN"
4. Логи → Docker + grep
bash
docker logs deployments-shop-1 --tail=50 | grep -i error
