1. Безопасно ли увеличивать ulimit -n?

Короткий ответ: ДА, безопасно, но с осторожностью.

Параметр	Было	Стало	Риск
ulimit -n	1024	65535	Минимальный
Что происходит: Каждое сетевое соединение (HTTP, WebSocket, PostgreSQL, Redis, NATS) занимает один файловый дескриптор.

Расчёт для 6000 пользователей:

6000 WebSocket соединений → 6000 fd
6000 HTTP запросов (одновременно) → ещё
Соединения с БД, Redis, NATS → ещё ~50
Итого нужно: ~12,000+ fd → 1024 не хватит!

Безопасно ли? Да, современные ядра Linux легко держат 65535 fd. Главное — не забыть, что каждый fd занимает память (~1KB). 65535 fd = ~65MB памяти.

# Временно (до перезагрузки) — безопасно
ulimit -n 65535

# Постоянно — нужно редактировать /etc/security/limits.conf
sudo nano /etc/security/limits.conf

# Добавить строки:
* soft nofile 65535
* hard nofile 65535
root soft nofile 65535
root hard nofile 65535

# После этого перезайти в систему
Проверка:

bash
ulimit -n  # должно показать 65535
