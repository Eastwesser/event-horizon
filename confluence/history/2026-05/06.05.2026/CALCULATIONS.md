Б. Подсчёт на сервере (бэкенд) ✅ ТВОЙ ВЫБОР

Клиент отправляет seed + массив ходов
Сервер переигрывает партию и считает очки сам
Плюсы: честно, надёжно, можно показать на собеседовании
Минусы: больше работы, нужно реализовать эмуляцию игры
Ты выбрал Путь В — полная валидация на сервере. Это значит, что фронтенд не считает очки вообще. Он нужен только для:

Отрисовки доски (по seed)
Регистрации ходов игрока
Отправки seed + moves на сервер
А сервер:

Восстанавливает доску из seed
Применяет все ходы из moves
Сам подсчитывает очки
Сравнивает с тем, что прислал клиент (или просто возвращает честный счёт)
Исправляем архитектуру

Фронтенд (React) отправляет:

json
{
  "user_id": "user-001",
  "game_id": "hexagon",
  "level": 3,
  "seed": "deterministic_seed_123",
  "moves": [
    {"fromX": 0, "fromY": 0, "toX": 1, "toY": 1, "timestamp": 1000},
    {"fromX": 1, "fromY": 1, "toX": 2, "toY": 2, "timestamp": 2000}
  ]
}
ВНИМАНИЕ: Поле score не нужно! Сервер сам его вычислит.

Сервер (Game) отвечает:

json
{
  "success": true,
  "new_highscore": 250,      // честно вычислено
  "lamps_earned": 10,
  "tickets_earned": 2
}
