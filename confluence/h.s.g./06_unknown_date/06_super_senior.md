1. Leader Election (Выбор лидера) — стоит знать базово
Где используется:

Kafka — один брокер — лидер партиции

Redis Sentinel — выбирает мастер-ноду

ZooKeeper / etcd — внутренний механизм

Суть:
В распределённой системе нужен единый координатор (leader), который принимает решения. Остальные — фолловеры. Если лидер падает — выбирается новый.

Фраза для интервью:

«Leader election — механизм выбора единственного координатора в кластере. Используется в Kafka (лидер партиции), Redis Sentinel, ZooKeeper. Алгоритмы: Raft, Paxos, или упрощённые (например, через ZooKeeper).»

2. Quorum (Кворум) — стоит знать базово
Где используется:

Репликация БД (Cassandra, DynamoDB)

Консенсус (Raft)

Kafka (ISR, min.insync.replicas)

Суть:
Кворум — это минимальное количество узлов, которые должны согласиться для принятия решения. Обычно: N/2 + 1 (большинство).

Пример:

3 реплики → кворум = 2

5 реплик → кворум = 3

Фраза для интервью:

«Quorum — минимальное количество узлов для принятия решения. Например, в Kafka min.insync.replicas=2 при 3 репликах. В Cassandra — для чтения и записи можно настроить разные кворумы (ONE, QUORUM, ALL).»

3. Raft / Paxos — для Senior
Что это:
Алгоритмы консенсуса — как узлы в распределённой системе договариваются о едином состоянии.

Где используется:

etcd, ZooKeeper, Consul (Raft)

Google Spanner, Amazon DynamoDB (Paxos)

Нужно ли знать для Middle:

Нет, достаточно знать, что они существуют.

Для Senior — да, базовое понимание.

Фраза для интервью:

«Raft и Paxos — алгоритмы консенсуса. Raft проще для понимания: выбирается лидер, он принимает решения, фолловеры реплицируют лог. Используется в etcd, ZooKeeper (раньше), Consul.»

4. Bloom Filters — редко
Что это:
Вероятностная структура данных, которая отвечает на вопрос: «Элемент точно НЕ в множестве?».

Где используется:

Cassandra (для проверки наличия данных в SSTable)

Redis (Bloom filter module)

Анти-спам системы

Нужно ли знать:
Редко спрашивают. Достаточно знать, что существует.

Фраза для интервью:

«Bloom filter — вероятностная структура данных. Она может сказать «элемента точно нет» или «элемент может быть». Используется для экономии памяти, когда допустима малая вероятность ложноположительного срабатывания.»

5. Gossip Protocol — стоит знать базово
Что это:
Протокол распространения информации в кластере по принципу «сплетен» — каждый узел периодически обменивается данными со случайными соседями.

Где используется:

Cassandra (распространение информации о состоянии нод)

Consul (memberlist)

Redis Cluster

Нужно ли знать:
Базово — да. Уметь объяснить, зачем нужен.

Фраза для интервью:

«Gossip protocol — децентрализованный способ распространения информации в кластере. Каждый узел периодически общается со случайными соседями, передавая известную ему информацию. Через несколько циклов все узлы узнают об изменениях. Используется в Cassandra, Consul, Redis Cluster.»
