# REST vs RPC

## Грейд
18

## Вопрос
В чем разница между REST и RPC подходами?

## Ответ

- **REST** строится вокруг ресурсов и операций над ними (GET, PUT, DELETE и т.д.)
- **RPC** — вызов методов сервиса (как локальных функций)

## Дополнительные вопросы

### Обязательно ли делать REST поверх HTTP?
Да.

### Обязательно ли делать RPC поверх HTTP?
Нет, можно делать поверх чего угодно (TCP, UDP, gRPC, AMQP).

### Расскажи, как RPC-запрос можно переложить на HTTP-запрос?
Передавать имя сервиса/метода в URL'е или заголовке.

### А как это сделать, используя только TCP?
Отправить сериализованный запрос (например, Protobuf) с указанием метода и аргументов.

## Что важно сказать на собеседовании

| Характеристика | REST | RPC |
|----------------|------|-----|
| Ориентация | Ресурсы | Действия |
| HTTP-методы | GET, POST, PUT, DELETE | POST (обычно) |
| URL | `/users/123` | `/users.getById` |
| Идемпотентность | GET, PUT, DELETE — да | Зависит от метода |
| Кэширование | Встроенное (HTTP cache) | Нет |
| Безопасность | Стандартные HTTP-механизмы | Зависит от реализации |

## Примеры

**REST:**

```text
GET /users/123
POST /users
DELETE /users/123
```

**RPC (в стиле JSON-RPC):**
```json
{
    "jsonrpc": "2.0",
    "method": "users.getById",
    "params": {"id": 123},
    "id": 1
}
```

**gRPC (современный RPC):**

```protobuf
service UserService {
    rpc GetById (GetByIdRequest) returns (User);
}
```
