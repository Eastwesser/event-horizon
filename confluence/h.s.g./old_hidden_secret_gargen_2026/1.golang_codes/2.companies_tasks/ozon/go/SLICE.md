# Слайсы (Slices) в Go

## Грейд
17-18

## Вопрос
Что такое слайс? Как он устроен?

## Ответ

**Слайс** — это абстракция над массивом, динамическая структура данных, представляющая собой часть массива.

### Внутреннее устройство

```go
type slice struct {
    array unsafe.Pointer  // указатель на underlying array
    len   int             // длина (количество элементов)
    cap   int             // вместимость (ёмкость underlying array)
}
```

### Отличия от массива
```text
Массив	                        Слайс
Фиксированный размер	        Динамический размер
Значение (копируется целиком)	Ссылочный тип (копируется заголовок)
[3]int	                        []int
```

## Дополнительные вопросы

### Как создаются слайсы?
```go
// Через make
s := make([]int, 5)     // len=5, cap=5
s := make([]int, 5, 10) // len=5, cap=10

// Через литерал
s := []int{1, 2, 3}     // len=3, cap=3

// Через слайсинг (slicing)
s2 := s[1:3]            // len=2, cap=cap(s)-1 (если s — массив или слайс)
```

### Как происходит рост слайса при append?

Правила (из runtime/slice.go):
```text
Размер (cap)	Рост
cap < 1024	    Удваивается
cap >= 1024	    Увеличивается на 25%
```
Важно: эти правила могут меняться в зависимости от размера элемента.

```go
s := make([]int, 0, 1)
s = append(s, 1)   // cap был 1 → стал 2
s = append(s, 2)   // cap был 2 → стал 4
s = append(s, 3, 4) // cap был 4 → стал 8
```

### Что произойдёт при слайсинге с указанием capacity?

```go
s := make([]int, 5, 10)
s2 := s[1:3:5]  // len=2, cap=4 (5-1)
```

### Когда сборщик мусора удалит underlying array?

Когда ни один слайс не ссылается на элементы этого массива.
Проблема: если создать маленький слайс из большого, большой массив не освободится

```go
big := make([]byte, 1000000)
small := big[:10]  // big не освободится, пока small жив
// Решение: копировать
smallCopy := make([]byte, 10)
copy(smallCopy, small)
```

### Что важно сказать на собеседовании

- Слайс — это заголовок (3 поля: указатель, len, cap)
- Передача слайса в функцию копирует заголовок, но не underlying array
- append может вернуть новый слайс (с новым указателем)
- Не храните указатели на элементы слайса, если делаете append (может произойти переаллокация)

Пример с указателем (ловушка)

```go
s := []int{1, 2, 3}
p := &s[0]     // указатель на первый элемент
s = append(s, 4)  // если переаллокация, p указывает на старый массив!
*p = 10        // меняем мёртвую память
```
