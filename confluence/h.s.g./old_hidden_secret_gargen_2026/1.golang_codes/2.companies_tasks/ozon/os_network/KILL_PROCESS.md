# Как убить процесс в Linux

## Грейд
17-18

## Вопрос
Как убить процесс в Linux?

## Ответ

### Способы

| Команда | Описание |
|---------|----------|
| `kill <pid>` | Отправить SIGTERM (15) — вежливый запрос завершиться |
| `kill -9 <pid>` | Отправить SIGKILL (9) — безусловное убийство |
| `killall <process_name>` | Убить все процессы с указанным именем |
| `pkill <pattern>` | Убить по шаблону (регулярное выражение) |
| `top` → `k` | В интерактивном режиме |
| `htop` → `k` | В интерактивном режиме |

## Дополнительные вопросы

### Как найти PID процесса?

```bash
ps aux | grep <name>
pgrep <name>
pidof <name>
top / htop (визуально)
cat /var/run/<app>.pid  # если приложение пишет PID-файл
```

### Что такое сигнал -9?

Сигнал SIGKILL — безусловное завершение процесса. 
Процесс не может его перехватить или проигнорировать. 
Ядро немедленно убивает процесс без очистки (файлы не закрываются, дети остаются).

### Что делать, если я вызываю kill (SIGTERM), а процесс продолжает работать?

Некоторые процессы игнорируют SIGTERM (или перехватывают и не завершаются). Тогда нужно использовать kill -9 (SIGKILL).

### Что важно сказать на собеседовании

```text
Основные сигналы
Сигнал	            Значение	                            Можно перехватить
SIGHUP (1)	    Перезагрузка конфига / завершение	    Да
SIGINT (2)	    Ctrl+C	                            Да
SIGQUIT (3)	    Ctrl+\ (дамп памяти)	            Да
SIGKILL (9)	    Безусловное убийство	            Нет
SIGTERM (15)	    Вежливый запрос завершиться	            Да
SIGSTOP (19)	    Приостановка	                    Нет
SIGCONT (18)	    Возобновление	                    Да
```

### Что делает SIGTERM?

Посылает процессу сигнал завершения. Процесс может:
- Освободить ресурсы (закрыть файлы, соединения с БД)
- Завершить дочерние процессы
- Игнорировать (но это некрасиво)
- Как отправить сигнал из кода на Go?

```go
proc, _ := os.FindProcess(pid)
proc.Signal(syscall.SIGTERM)
proc.Kill() // SIGKILL
```

### Почему kill -9 — это плохо?
- Процесс не может корректно завершиться
- Файлы могут остаться незакрытыми (повреждение данных)
- Ресурсы не освобождаются (shm, sem)
- Дочерние процессы могут стать зомби или остаться висеть
