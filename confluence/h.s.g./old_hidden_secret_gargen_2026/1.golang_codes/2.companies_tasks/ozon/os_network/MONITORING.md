# Мониторинг и отладка микросервисов

## Грейд
17-19

## Вопрос
Какие существуют инструменты для мониторинга и отладки микросервисов?

## Ответ

### Основные подходы

| Подход | Что даёт | Примеры |
|--------|----------|---------|
| **Логи (Logs)** | События, ошибки, запросы | ELK, Loki, Splunk |
| **Метрики (Metrics)** | Графики, алерты, нагрузка | Prometheus, Grafana, Datadog |
| **Трассировка (Tracing)** | Взаимосвязи в распределённых системах | Jaeger, Zipkin |
| **Профилирование (Profiling)** | CPU, память, contention | pprof, py-spy |

## Дополнительные вопросы

### Пример инструментов для сбора и отображения метрик?
- **Prometheus** — сбор метрик (pull модель)
- **Grafana** — визуализация и дашборды
- **VictoriaMetrics** — альтернатива Prometheus для больших объёмов

### Какая тулза используется для профилирования в Go?
**pprof** (встроенный). Подключается через `net/http/pprof` или `runtime/pprof`.

### Зачем микросервису на Go нужен хендлер `/debug/vars`?
Отдаёт отладочную информацию:
- Использование памяти
- Статистика GC (количество, паузы)
- Goroutine count
- Переменные из `expvar`

```go
import _ "expvar"
// теперь доступно /debug/vars
```

### Как посмотреть логи микросервиса, живущего в Kubernetes?

```bash
kubectl logs <pod-name>
kubectl logs -f <pod-name>        # следить в реальном времени
kubectl logs --previous <pod-name> # предыдущий запуск (при падении)
```

### Четыре золотых сигнала мониторинга (Google SRE)
Сигнал	    Описание

Latency	    Время ответа
Traffic	    Количество запросов (RPS)
Errors	    Процент ошибок (5xx, 4xx, таймауты)
Saturation	Загруженность (CPU, память, соединения)

### USE метрики (для ресурсов)

Метрика	    Вопрос
Utilization	Как долго ресурс занят?
Saturation	Насколько велика очередь?
Errors	    Есть ли ошибки?
