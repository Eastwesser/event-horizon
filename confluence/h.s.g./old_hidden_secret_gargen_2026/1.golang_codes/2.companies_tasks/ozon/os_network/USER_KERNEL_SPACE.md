# User Space vs Kernel Space

## Грейд
18-19

## Вопрос
Что такое user space и kernel space? Зачем нужно такое разделение?

## Ответ

- **User space** — окружение и режим процессора, в котором работают прикладные программы. Доступна только виртуальная память текущего процесса, отсутствует часть низкоуровневых команд процессора.
- **Kernel space** — окружение, в котором работает ядро ОС. Доступен весь арсенал процессора: управление памятью, устройствами, привилегированные инструкции.

**Разделение нужно для безопасности** — прикладное ПО не может сломать систему или получить доступ к чужим данным.

## Дополнительные вопросы

### Как происходит переход между режимами?
При вызове приложением **сискола** (системного вызова) происходит переключение из user в kernel mode через специальную инструкцию процессора (например, `syscall` в x86-64).

### Что может делать только ядро?
- Управление памятью (включение/выключение страниц)
- Обработка прерываний
- Доступ к устройствам ввода-вывода
- Создание/уничтожение процессов

## Что важно сказать на собеседовании

### Защита памяти
Каждый процесс имеет изолированное виртуальное адресное пространство. Нет доступа к памяти других процессов без специальных механизмов (shared memory).

### Кольца защиты (rings)
x86 имеет 4 кольца защиты (ring 0 — самое привилегированное, ring 3 — user space). Linux использует только ring 0 (kernel) и ring 3 (user).

### Пример: что произойдёт при `make(chan int)` в Go?
Создание канала — это user space операция (не сискол), рантайм сам управляет памятью и синхронизацией. Но при нехватке памяти может понадобиться сискол `mmap`.
