# TCP vs UDP

## Грейд
17-19

## Вопрос
Чем различаются протоколы TCP и UDP?

## Ответ

| Характеристика | TCP | UDP |
|----------------|-----|-----|
| Соединение | Ориентирован на соединение (3-way handshake) | Без соединения |
| Надёжность | Гарантирует доставку, порядок, без дубликатов | Нет гарантий (пакеты могут теряться, дублироваться, переупорядочиваться) |
| Контроль потока | Есть (flow control, congestion control) | Нет |
| Скорость | Медленнее | Быстрее |
| Размер заголовка | 20-60 байт | 8 байт |
| Broadcast | Нет | Да (широковещательная рассылка) |

## Дополнительные вопросы

### Зачем нужен UDP, если он такой ненадёжный?
**Зато быстрее.** Отсутствие подтверждений, handshake'ов и контроля перегрузки даёт меньшую задержку.

### Зачем нужен TCP, если он такой медленный?
**Зато надёжный.** Механизм подтверждений гарантирует, что данные дойдут в правильном порядке.

### Опишите высокоуровневую схему TCP-соединения

**Серверная сторона:**
1. `socket()` — создание сокета
2. `bind()` — привязка к порту
3. `listen()` — начало прослушивания
4. `accept()` — принятие соединения (блокируется)

**Клиентская сторона:**
1. `socket()` — создание сокета
2. `connect()` — установка соединения (3-way handshake)

**Обмен:**
- `send()` / `recv()` — отправка и получение данных

**Завершение:**
- `close()` / `shutdown()` — закрытие соединения

### Где применяется UDP?

| Применение | Почему |
|------------|--------|
| Видео/аудио стриминг | Потеря кадра лучше, чем задержка |
| Торренты | Требуется скорость и broadcast |
| Онлайн-игры | Задержка критична |
| DNS | Короткие запросы, loss tolerance |
| VoIP | Реал-тайм важнее точности |
| DHCP | Широковещательный запрос |
