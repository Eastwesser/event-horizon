## 2. Message Flow (Send → Deliver → Read)

```
┌─────────────┐                                              ┌─────────────┐
│  Client A   │                                              │  Client B   │
│  (Sender)   │                                              │ (Receiver)  │
└──────┬──────┘                                              └──────▲──────┘
       │                                                             │
       │ 1. POST /chats/123/messages                                │
       │    {content: "Hello!", ...}                                │
       ▼                                                             │
┌──────────────────────────────────────────────────────────────────┴──────┐
│                          Chat Service                                    │
│                                                                           │
│  2. Validate request                                                     │
│  3. Check rate limit (Redis)                                             │
│  4. Generate message_id (UUID)                                           │
│  5. Save to PostgreSQL                                                   │
│     ┌─────────────────────────────────────────────────────────┐         │
│     │ INSERT INTO messages (message_id, chat_id, sender_id,   │         │
│     │   content, sent_at) VALUES (?, ?, ?, ?, NOW())          │         │
│     └─────────────────────────────────────────────────────────┘         │
│                                                                           │
│  6. Publish event to Kafka                                               │
│     ┌─────────────────────────────────────────────────────────┐         │
│     │ Topic: chat.messages.sent                               │         │
│     │ Payload: {message_id, chat_id, sender_id, content, ...} │         │
│     └─────────────────────────────────────────────────────────┘         │
│                                                                           │
│  7. Broadcast via Redis Pub/Sub                                          │
│     ┌─────────────────────────────────────────────────────────┐         │
│     │ PUBLISH chat:123:messages {message_id, content, ...}    │         │
│     └─────────────────────────────────────────────────────────┘         │
│                                                                           │
│  8. Update unread count (Redis)                                          │
│     ┌─────────────────────────────────────────────────────────┐         │
│     │ HINCRBY unread:user:456 chat:123 1                      │         │
│     └─────────────────────────────────────────────────────────┘         │
└──────────────────────┬────────────────────────────────────────┬──────────┘
                       │                                        │
                       │                                        │
       ┌───────────────▼─────────────┐      ┌──────────────────▼──────────┐
       │   WebSocket Gateway         │      │   Notification Service      │
       │   - Subscribed to Redis     │      │   - Consumer from Kafka     │
       └──────────────┬──────────────┘      └──────────────┬──────────────┘
                      │                                     │
                      │ 9. Push via WebSocket               │ 10. Send Push
                      │    (if user online)                 │     (if offline)
                      ▼                                     ▼
               ┌──────────────┐                      ┌──────────────┐
               │  Client B    │                      │     FCM      │
               │  (Receiver)  │                      │   (Firebase) │
               └──────┬───────┘                      └──────┬───────┘
                      │                                     │
                      │ 11. ACK "delivered"                 │
                      │     POST /messages/{id}/delivered   │
                      ▼                                     ▼
               ┌──────────────────────────────────────────────────┐
               │           Chat Service                            │
               │  UPDATE messages SET delivered_at = NOW()        │
               │  WHERE message_id = ?                            │
               └──────────────────────────────────────────────────┘
                      │
                      │ 12. User opens chat
                      │     POST /chats/123/mark-read
                      ▼
               ┌──────────────────────────────────────────────────┐
               │           Chat Service                            │
               │  UPDATE messages SET read_at = NOW()             │
               │  WHERE chat_id = ? AND receiver_id = ?           │
               │  AND read_at IS NULL                             │
               │                                                   │
               │  HSET unread:user:456 chat:123 0                 │
               └──────────────────────────────────────────────────┘
```

## 3. WebSocket: Sticky Sessions + Redis Pub/Sub

```
┌──────────────────────────────────────────────────────────────────────────┐
│                          Load Balancer                                    │
│                    (Consistent Hashing by user_id)                        │
└────────┬──────────────────────┬──────────────────────┬────────────────────┘
         │                      │                      │
         │ user_id % 3 = 0      │ user_id % 3 = 1      │ user_id % 3 = 2
         ▼                      ▼                      ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  WS Server 1    │    │  WS Server 2    │    │  WS Server 3    │
│                 │    │                 │    │                 │
│ Connected:      │    │ Connected:      │    │ Connected:      │
│ - user_100      │    │ - user_101      │    │ - user_102      │
│ - user_103      │    │ - user_104      │    │ - user_105      │
│ - ...           │    │ - ...           │    │ - ...           │
└────────┬────────┘    └────────┬────────┘    └────────┬────────┘
         │                      │                      │
         └──────────────────────┼──────────────────────┘
                                │
                                │ SUBSCRIBE chat:*:messages
                                ▼
                    ┌────────────────────────┐
                    │      Redis Pub/Sub     │
                    │                        │
                    │ Channels:              │
                    │ - chat:123:messages    │
                    │ - chat:456:messages    │
                    │ - ...                  │
                    └───────────▲────────────┘
                                │
                                │ PUBLISH
                                │
                    ┌───────────┴────────────┐
                    │     Chat Service       │
                    │                        │
                    │ New message arrived    │
                    │ → PUBLISH to Redis     │
                    └────────────────────────┘

Как это работает:
1. User 100 подключается к WS Server 1 (sticky session)
2. User 101 отправляет сообщение в chat:123 (где user 100 участник)
3. Chat Service публикует в Redis: PUBLISH chat:123:messages {message_id, ...}
4. Все WS серверы подписаны на chat:*:messages
5. WS Server 1 получает событие и отправляет user 100 через WebSocket
6. WS Server 2, 3 тоже получают, но у них нет user 100 → игнорируют
```

## 4. Data Partitioning: Time-based (PostgreSQL)

```
┌────────────────────────────────────────────────────────────────────────┐
│                          messages (Parent Table)                        │
└────────────────────────────────────────────────────────────────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │                           │                           │
        ▼                           ▼                           ▼
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│ messages_2025_01 │      │ messages_2025_02 │      │ messages_2025_03 │
│                  │      │                  │      │                  │
│ FOR VALUES FROM  │      │ FOR VALUES FROM  │      │ FOR VALUES FROM  │
│ '2025-01-01'     │      │ '2025-02-01'     │      │ '2025-03-01'     │
│ TO '2025-02-01'  │      │ TO '2025-03-01'  │      │ TO '2025-04-01'  │
│                  │      │                  │      │                  │
│ Size: ~30 GB     │      │ Size: ~30 GB     │      │ Size: ~30 GB     │
│ Rows: ~90M       │      │ Rows: ~90M       │      │ Rows: ~90M       │
└──────────────────┘      └──────────────────┘      └──────────────────┘

Query optimization:
┌─────────────────────────────────────────────────────────────────┐
│ SELECT * FROM messages                                          │
│ WHERE chat_id = '123' AND sent_at > '2025-02-01';              │
│                                                                 │
│ PostgreSQL Planner:                                             │
│ → Partition Pruning: только messages_2025_02 и messages_2025_03│
│ → Index Scan: idx_chat_sent (chat_id, sent_at DESC)            │
└─────────────────────────────────────────────────────────────────┘

Monthly ETL job (архивация):
┌─────────────────────────────────────────────────────────────────┐
│ 1. SELECT * FROM messages_2024_12                               │
│    WHERE sent_at < NOW() - INTERVAL '30 days'                   │
│                                                                 │
│ 2. Batch INSERT INTO Cassandra                                  │
│    (по 1000 строк)                                              │
│                                                                 │
│ 3. Verify data in Cassandra                                     │
│                                                                 │
│ 4. DROP TABLE messages_2024_12;                                 │
│    (освобождаем место в PostgreSQL)                             │
└─────────────────────────────────────────────────────────────────┘
```

## 5. Cassandra Data Model

```
┌────────────────────────────────────────────────────────────────────────┐
│                    messages_archive (Cassandra)                         │
├────────────────────────────────────────────────────────────────────────┤
│ PRIMARY KEY (chat_id, sent_at, message_id)                             │
│ CLUSTERING ORDER BY (sent_at DESC)                                     │
└────────────────────────────────────────────────────────────────────────┘

Partition Strategy:
┌──────────────────────────────────────────────────────────────────────┐
│  chat_id (Partition Key) → Все сообщения чата на одном узле         │
│                                                                      │
│  chat:123 ──────────────────────────────────────────────────────┐   │
│                                                                   │   │
│  ┌──────────────────────────────────────────────────────────────▼─┐ │
│  │ Node 1                                                          │ │
│  │ ┌──────────────────────────────────────────────────────────┐   │ │
│  │ │ Partition: chat:123                                      │   │ │
│  │ │ ┌────────────────────────────────────────────────────┐   │   │ │
│  │ │ │ sent_at: 2024-12-31 23:59:59 | message_id: abc123 │   │   │ │
│  │ │ │ sent_at: 2024-12-31 23:58:30 | message_id: def456 │   │   │ │
│  │ │ │ sent_at: 2024-12-31 23:57:15 | message_id: ghi789 │   │   │ │
│  │ │ │ ... (sorted by sent_at DESC)                       │   │   │ │
│  │ │ └────────────────────────────────────────────────────┘   │   │ │
│  │ └──────────────────────────────────────────────────────────┘   │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  Query efficiency:                                                   │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │ SELECT * FROM messages_archive                                 │ │
│  │ WHERE chat_id = '123' AND sent_at > '2024-12-01'              │ │
│  │ LIMIT 50;                                                      │ │
│  │                                                                │ │
│  │ → Single partition scan (локальность данных)                  │ │
│  │ → Clustering order → sorted automatically                     │ │
│  └────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘

TTL (Time-To-Live):
┌────────────────────────────────────────────────────────────────────┐
│ CREATE TABLE messages_archive (...)                                │
│ WITH default_time_to_live = 63072000;  -- 2 года в секундах       │
│                                                                    │
│ Automatic deletion:                                                │
│ ┌────────────────────────────────────────────────────────────┐    │
│ │ sent_at: 2023-02-10 → TTL expired → Tombstone → Compaction│    │
│ └────────────────────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────────────┘
```

## 7. Rate Limiting: Token Bucket

```
┌────────────────────────────────────────────────────────────────┐
│                    Token Bucket Algorithm                       │
├────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Bucket capacity: 30 tokens                                     │
│  Refill rate: 30 tokens per 60 seconds (0.5 tokens/s)          │
│                                                                 │
│  ┌────────────────────────────────────────────────────────┐    │
│  │                     Redis State                         │    │
│  │  key: rate_limit:user:123                               │    │
│  │  value: {                                               │    │
│  │    tokens: 25,      // Текущее количество токенов      │    │
│  │    last_refill: 1644500000  // Unix timestamp          │    │
│  │  }                                                      │    │
│  └────────────────────────────────────────────────────────┘    │
│                                                                 │
│  Request flow:                                                  │
│  ┌────────────────────────────────────────────────────────┐    │
│  │ 1. User отправляет сообщение                           │    │
│  │                                                         │    │
│  │ 2. GET rate_limit:user:123                             │    │
│  │    → tokens: 25, last_refill: 1644500000               │    │
│  │                                                         │    │
│  │ 3. Вычисляем сколько токенов восстановилось:           │    │
│  │    elapsed = now - last_refill = 10 секунд             │    │
│  │    refilled = elapsed × 0.5 = 5 токенов                │    │
│  │    new_tokens = min(25 + 5, 30) = 30 токенов           │    │
│  │                                                         │    │
│  │ 4. Проверяем доступность токена:                        │    │
│  │    if new_tokens > 0:                                   │    │
│  │      → Разрешено (consume 1 token)                     │    │
│  │      → SET rate_limit:user:123 {tokens: 29, ...}       │    │
│  │    else:                                                │    │
│  │      → 429 Too Many Requests                           │    │
│  └────────────────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────────┘

Visualization:
Time: 0s    [████████████████████████████████] 30/30 tokens
Time: 10s   [████████████████████████████████] 30/30 (refilled +5)
User sends 5 messages
Time: 10s   [█████████████████████████░░░░░░] 25/30 tokens
Time: 20s   [████████████████████████████████] 30/30 (refilled +5)
User sends 30 messages rapidly
Time: 20s   [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░] 0/30 tokens
Time: 21s   Next request → 429 Too Many Requests
Time: 80s   [████████████████████████████████] 30/30 (fully refilled)
```

## 8. Multi-Region Setup (Disaster Recovery)

```
┌─────────────────────────────────────────────────────────────────────┐
│                          Global DNS (Route53)                        │
│                 Latency-based routing / Geolocation                  │
└───────────────────────┬───────────────────────┬──────────────────────┘
                        │                       │
         ┌──────────────▼────────┐   ┌──────────▼──────────────┐
         │   Region: US-EAST-1   │   │   Region: EU-WEST-1     │
         │   (Primary)           │   │   (Secondary/Standby)   │
         └──────────┬────────────┘   └──────────┬──────────────┘
                    │                           │
      ┌─────────────┼───────────────────────────┼─────────────┐
      │             │                           │             │
      ▼             ▼                           ▼             ▼
┌──────────┐  ┌──────────┐              ┌──────────┐  ┌──────────┐
│Chat Svc  │  │  WS GW   │              │Chat Svc  │  │  WS GW   │
│10 nodes  │  │10 nodes  │              │10 nodes  │  │10 nodes  │
└────┬─────┘  └────┬─────┘              └────┬─────┘  └────┬─────┘
     │             │                         │             │
     ▼             ▼                         ▼             ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│     PostgreSQL Primary       │──▶│   PostgreSQL Read Replica    │
│     (Write + Read)           │   │   (Read-only, async replica) │
└──────────────────────────────┘   └──────────────────────────────┘
          │                                     ▲
          │ Streaming Replication               │
          └─────────────────────────────────────┘

Failover scenario:
┌────────────────────────────────────────────────────────────────┐
│ 1. US-EAST-1 region failure detected                           │
│    (health checks fail for 3 consecutive times)                │
│                                                                │
│ 2. Route53 автоматически переключает DNS на EU-WEST-1         │
│    (TTL = 60 seconds → полное переключение за 2-3 минуты)     │
│                                                                │
│ 3. EU-WEST-1 PostgreSQL replica промоутится в Primary         │
│    (pg_promote или AWS RDS automatic failover)                │
│                                                                │
│ 4. Chat Service в EU-WEST-1 начинает принимать write          │
│                                                                │
│ 5. RTO (Recovery Time Objective): ~5 минут                    │
│    RPO (Recovery Point Objective): ~30 секунд (async replica) │
└────────────────────────────────────────────────────────────────┘
```
