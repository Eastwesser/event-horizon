# Semaphore: Инсайты от Мусаси

## 🔑 Суть паттерна

**Semaphore (семафор)** — примитив синхронизации, который ограничивает количество одновременных доступов к ресурсу.

**Принцип:** Максимум N горутин могут одновременно работать с ресурсом (где N — количество "билетов").

**Аналогия:** Пропускная система — у тебя есть N пропусков. Горутина берёт пропуск, работает, возвращает пропуск. Если все пропуски заняты, следующая ждёт.

## 📊 Когда использовать?

- **Ограничение конкурентности:** не более N одновременных запросов к API
- **Ограничение ресурсов:** не более N одновременных подключений к БД
- **Rate limiting:** ограничение количества одновременных операций
- **Worker Pool:** ограничение количества воркеров

**Примеры:**
- Сервер: не более 100 одновременных HTTP-запросов
- БД: не более 10 одновременных подключений
- Файловая система: не более 5 одновременных операций записи
- Скачивание: не более 3 одновременных загрузок

## 🏗️ Архитектура

```
Семафор (N билетов)
    ↓
[Билет 1] [Билет 2] [Билет 3] ... [Билет N]
    ↓
Горутина 1 берёт билет → работает → возвращает билет
Горутина 2 берёт билет → работает → возвращает билет
...
Горутина M ждёт (если все билеты заняты)
```

**Важно:** Семафор не гарантирует порядок доступа. Первая горутина, которая освободит билет, получит доступ следующей ожидающей горутине.

## ⚙️ Реализация

### Базовая реализация через канал

```go
type Semaphore struct {
    tickets chan struct{} // Буферизованный канал для хранения "билетов"
}

func NewSemaphore(ticketsNumber int) *Semaphore {
    return &Semaphore{
        tickets: make(chan struct{}, ticketsNumber),
    }
}

// Acquire берёт билет (блокируется, если все билеты заняты)
func (s *Semaphore) Acquire() {
    s.tickets <- struct{}{} // Запись блокируется, если канал полон
}

// Release возвращает билет
func (s *Semaphore) Release() {
    <-s.tickets // Читаем билет обратно
}
```

**Как это работает:**
1. Создаём буферизованный канал на N элементов
2. `Acquire()` — записываем в канал (блокируется, если канал полон)
3. `Release()` — читаем из канала (освобождаем место)

### Использование

```go
semaphore := NewSemaphore(3) // Максимум 3 одновременных доступа

for i := 0; i < 10; i++ {
    go func(workerID int) {
        semaphore.Acquire() // Берём билет
        defer semaphore.Release() // Возвращаем билет
        
        // Критическая секция (работа с ресурсом)
        doWork(workerID)
    }(i)
}
```

## 🔄 Semaphore vs Mutex

| Аспект | Semaphore | Mutex |
|--------|-----------|-------|
| **Количество доступов** | N (настраивается) | 1 (только один) |
| **Использование** | Ограничение ресурсов | Взаимное исключение |
| **Когда использовать** | Ограничение конкурентности | Защита критической секции |
| **Реализация** | Буферизованный канал | `sync.Mutex` |

**Пример:**
```go
// Mutex: только 1 горутина может работать
var mu sync.Mutex
mu.Lock()
defer mu.Unlock()
// Критическая секция

// Semaphore: до 3 горутин могут работать одновременно
sem := NewSemaphore(3)
sem.Acquire()
defer sem.Release()
// Критическая секция
```

## 🔄 Semaphore vs Rate Limiter

| Аспект | Semaphore | Rate Limiter |
|--------|-----------|--------------|
| **Ограничение** | Одновременные доступы | Запросы в единицу времени |
| **Пример** | Не более 10 одновременных запросов | Не более 100 запросов в секунду |
| **Когда использовать** | Ограничение ресурсов | Ограничение частоты |

**Пример:**
```go
// Semaphore: не более 10 одновременных запросов
sem := NewSemaphore(10)
sem.Acquire()
defer sem.Release()
makeRequest()

// Rate Limiter: не более 100 запросов в секунду
limiter := NewRateLimiter(100, time.Second)
limiter.Allow()
makeRequest()
```

## ⚠️ Ловушки

### 1. Acquire в главной горутине

**Проблема:** Если `Acquire()` вызывается в главной горутине до запуска горутин, все горутины получат доступ одновременно.

```go
// ПЛОХО: все Acquire() вызываются последовательно в главной горутине
for i := 0; i < 6; i++ {
    semaphore.Acquire() // Главная горутина блокируется здесь
    go func() {
        defer semaphore.Release()
        doWork()
    }()
}
// Результат: все 6 горутин получат доступ (если семафор на 5, то 5 сразу, 1 ждёт)

// ХОРОШО: Acquire() вызывается внутри горутины
for i := 0; i < 6; i++ {
    go func() {
        semaphore.Acquire() // Горутина конкурирует за доступ
        defer semaphore.Release()
        doWork()
    }()
}
```

### 2. Забытый Release

**Проблема:** Если забыть вызвать `Release()`, билет не вернётся, и семафор "заблокируется".

**Решение:** Всегда используй `defer` для `Release()`.

```go
semaphore.Acquire()
defer semaphore.Release() // Гарантированно вернёт билет
// Работа
```

### 3. Паника в критической секции

**Проблема:** Если горутина паникует до `Release()`, билет не вернётся.

**Решение:** `defer` гарантирует вызов `Release()` даже при панике.

```go
semaphore.Acquire()
defer semaphore.Release() // Вызовется даже при панике
// Работа (может паниковать)
```

### 4. Неправильный порядок Acquire/Release

**Проблема:** Если вызвать `Release()` без `Acquire()`, произойдёт deadlock (чтение из пустого канала).

**Решение:** Всегда парно использовать `Acquire()` и `Release()`.

```go
// ПЛОХО: Release без Acquire
semaphore.Release() // Deadlock: чтение из пустого канала

// ХОРОШО: парное использование
semaphore.Acquire()
defer semaphore.Release()
```

## 💡 Вопросы для размышления

1. **Почему семафор реализован через буферизованный канал?** (Запись блокируется, когда канал полон — это и есть ограничение)
2. **Что произойдёт, если вызвать `Release()` больше раз, чем `Acquire()`?** (Deadlock: чтение из пустого канала)
3. **Можно ли использовать семафор вместо мьютекса?** (Да, семафор на 1 билет эквивалентен мьютексу)
4. **В чём разница между семафором и Worker Pool?** (Семафор — примитив синхронизации. Worker Pool — паттерн архитектуры)
5. **Как семафор связан с контекстом?** (Можно добавить `context.Context` для отмены ожидания)

## 🔧 Практические примеры

### Пример 1: Ограничение HTTP-запросов

```go
semaphore := NewSemaphore(10) // Не более 10 одновременных запросов

for _, url := range urls {
    go func(u string) {
        semaphore.Acquire()
        defer semaphore.Release()
        
        resp, err := http.Get(u)
        // Обработка ответа
    }(url)
}
```

### Пример 2: Ограничение подключений к БД

```go
dbSemaphore := NewSemaphore(5) // Не более 5 одновременных подключений

func queryDB(query string) {
    dbSemaphore.Acquire()
    defer dbSemaphore.Release()
    
    db.Exec(query)
}
```

### Пример 3: Ограничение операций с файлами

```go
fileSemaphore := NewSemaphore(3) // Не более 3 одновременных операций

func writeFile(filename string, data []byte) error {
    fileSemaphore.Acquire()
    defer fileSemaphore.Release()
    
    return os.WriteFile(filename, data, 0644)
}
```


### Пример 4: Семафор как мьютекс

```go
// Семафор на 1 билет = мьютекс
mutex := NewSemaphore(1)

mutex.Acquire()
defer mutex.Release()
// Критическая секция (только 1 горутина)
```

### Пример 5: Семафор с контекстом (отмена ожидания)

```go
type SemaphoreWithContext struct {
    tickets chan struct{}
}

func (s *SemaphoreWithContext) AcquireWithContext(ctx context.Context) error {
    select {
    case s.tickets <- struct{}{}:
        return nil // Получили билет
    case <-ctx.Done():
        return ctx.Err() // Отмена ожидания
    }
}
```

## 🎯 Преимущества Semaphore

1. **Гибкость:** можно настроить любое количество одновременных доступов
2. **Простота:** простая реализация через канал
3. **Безопасность:** гарантирует ограничение ресурсов
4. **Масштабируемость:** легко изменить количество билетов

## 🔄 Semaphore vs Worker Pool

| Аспект | Semaphore | Worker Pool |
|--------|-----------|-------------|
| **Назначение** | Ограничение доступа к ресурсу | Пул воркеров для обработки задач |
| **Реализация** | Примитив синхронизации | Архитектурный паттерн |
| **Использование** | Защита ресурса | Обработка очереди задач |

**Связь:** Worker Pool часто использует семафор для ограничения количества воркеров.

```go
// Worker Pool с семафором
semaphore := NewSemaphore(5) // Максимум 5 воркеров

for task := range taskQueue {
    go func(t Task) {
        semaphore.Acquire()
        defer semaphore.Release()
        
        processTask(t)
    }(task)
}
```

## 🔧 Расширенная реализация (с контекстом)

```go
type Semaphore struct {
    tickets chan struct{}
}

func (s *Semaphore) AcquireWithContext(ctx context.Context) error {
    select {
    case s.tickets <- struct{}{}:
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

// Использование
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

err := semaphore.AcquireWithContext(ctx)
if err != nil {
    return fmt.Errorf("timeout waiting for semaphore: %w", err)
}
defer semaphore.Release()
```
