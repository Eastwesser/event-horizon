# Filter: Инсайты от Мусаси

## 🔑 Суть паттерна

**Filter (фильтр для каналов)** — пропускает только те элементы, которые проходят условие (предикат).

**Принцип:** Канал типа `T` → канал типа `T` (только подходящие элементы)

**Аналогия:** Сито — пропускает только то, что проходит через отверстия.

## 📊 Когда использовать?

- **Фильтрация данных:** оставить только подходящие элементы
- **Валидация:** пропустить только валидные данные
- **Условная обработка:** обработать только элементы, удовлетворяющие условию
- **Очистка данных:** убрать нежелательные элементы из потока

## 🏗️ Архитектура

```
Входной канал (T) ──> Filter ──> Выходной канал (T)
                      (предикат)
                      ↓
                  [1,2,3,4,5] → [2,4] (только чётные)
```

**Важно:** На выходе **меньше или столько же** элементов, сколько на входе (никогда больше).

## ⚙️ Реализация

```go
func Filter[T any](inputCh <-chan T, predicate func(T) bool) <-chan T {
    outputCh := make(chan T)
    
    go func() {
        defer close(outputCh)
        for value := range inputCh {
            if predicate(value) {
                outputCh <- value  // Пропускаем только подходящие
            }
            // Если predicate(value) == false, элемент просто пропускается
        }
    }()
    
    return outputCh
}
```

**Использование:**
```go
numbers := make(chan int)
evenNumbers := Filter(numbers, func(n int) bool {
    return n%2 == 0  // Только чётные числа
})
```

## 🔄 Filter vs Decorator

| Аспект | Filter | Decorator |
|--------|--------|-----------|
| **Преобразование** | Нет (тип не меняется) | Да (может изменить тип) |
| **Количество элементов** | Меньше или равно | Равно (все элементы) |
| **Функция** | `func(T) bool` (предикат) | `func(T) T` или `func(T) U` |
| **Назначение** | Отфильтровать | Преобразовать |

**Пример:**
```go
// Decorator: преобразует все элементы
decorated := Decorate(numbers, func(n int) int { return n * 2 })
// [1,2,3] → [2,4,6] (все элементы, преобразованные)

// Filter: пропускает только подходящие
filtered := Filter(numbers, func(n int) bool { return n%2 == 0 })
// [1,2,3] → [2] (только чётные)
```

## 🎯 Предикат (Predicate)

**Предикат** — функция, которая возвращает `bool` для каждого элемента.

**Примеры предикатов:**
```go
// Проверка на чётность
isEven := func(n int) bool { return n%2 == 0 }

// Проверка на валидность
isValid := func(u User) bool { return u.Age >= 18 }

// Проверка на наличие
hasValue := func(s string) bool { return s != "" }
```

**Название:** "Предикат" пришло из математики и логики — это утверждение, которое может быть истинным или ложным.

## ⚠️ Ловушки

### 1. Незакрытый канал

**Проблема:** Если входной канал не закрыт, Filter будет ждать бесконечно.

**Решение:**
```go
go func() {
    defer close(inputCh)  // Всегда закрываем после записи
    for i := 0; i < 10; i++ {
        inputCh <- i
    }
}()
```

### 2. Пустой результат

**Вопрос:** Что произойдёт, если ни один элемент не прошёл фильтр?

**Ответ:** Выходной канал будет пустым, но корректно закрытым. `range` просто не выполнится.

```go
// Если все элементы отфильтрованы
for value := range Filter(channel, impossibleCondition) {
    // Этот блок не выполнится
}
// Программа продолжит работу нормально
```

### 3. Буферизованные каналы

**Вопрос:** Нужен ли буфер для `outputCh`?

**Ответ:** Обычно не нужен, так как:
- Filter может пропускать элементы (меньше данных на выходе)
- Но если обработка медленная, буфер может помочь

## 💡 Вопросы для размышления

1. Можно ли комбинировать Filter и Decorator? (Да: `Filter(Decorate(ch, fn1), fn2)`)
2. Что произойдёт, если предикат паникует? (Горутина упадёт, канал не закроется)
3. Можно ли сделать Filter, который возвращает два канала (прошедшие и не прошедшие)? (Да, это паттерн "Split")

## 🎯 Связь с другими паттернами

- **Decorator** — противоположность (преобразует все элементы)
- **Pipeline** — можно комбинировать: `Filter → Decorator → Filter`
- **Fan-Out + Filter + Fan-In** — распределение → фильтрация → сбор

## 🔧 Практические примеры

### Пример 1: Фильтрация пользователей
```go
users := make(chan User)
adults := Filter(users, func(u User) bool {
    return u.Age >= 18
})
```

### Пример 2: Фильтрация ошибок
```go
results := make(chan Result)
successful := Filter(results, func(r Result) bool {
    return r.Error == nil
})
```

### Пример 3: Фильтрация по типу (с type assertion)
```go
items := make(chan interface{})
strings := Filter(items, func(item interface{}) bool {
    _, ok := item.(string)
    return ok
})
```

### Пример 4: Комбинация Filter + Decorator
```go
numbers := make(chan int)
// Сначала фильтруем (только чётные), потом преобразуем (умножаем на 2)
processed := Decorate(
    Filter(numbers, func(n int) bool { return n%2 == 0 }),
    func(n int) int { return n * 2 },
)
```

## 🔄 Filter vs Separator

**Вопрос:** Почему "Filter", а не "Separator"?

**Ответ:**
- **Filter** — стандартное название в функциональном программировании (как в Haskell, JavaScript, Python)
- **Separator** — более общее понятие (может означать разделение на несколько потоков)
- **Filter** — конкретно означает "пропустить только подходящие"

**Аналогия:**
- Filter = сито (пропускает только подходящее)
- Separator = разделитель (может разделять на несколько частей)
