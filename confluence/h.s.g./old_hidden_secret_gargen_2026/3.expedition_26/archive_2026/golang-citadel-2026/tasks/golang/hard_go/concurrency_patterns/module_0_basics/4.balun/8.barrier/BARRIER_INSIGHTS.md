# Barrier: Инсайты от Мусаси

## 🔑 Суть паттерна

**Barrier (барьер синхронизации)** — примитив синхронизации, который заставляет N горутин ждать друг друга, пока все не достигнут точки синхронизации.

**Принцип:** Все горутины должны "встретиться" в одной точке, прежде чем продолжить выполнение.

**Аналогия:** Группа туристов идёт по тропе. Все должны дойти до контрольной точки, прежде чем продолжить путь. Самый медленный определяет скорость группы.

**Важно:** НЕ ПУТАТЬ с барьерами памяти (memory barriers) — это разные концепции!

## 📊 Когда использовать?

- **Синхронизация фаз:** все горутины должны завершить фазу 1 перед началом фазы 2
- **Координация воркеров:** все воркеры должны завершить задачу перед началом следующей
- **Параллельные алгоритмы:** синхронизация итераций в параллельных вычислениях
- **Симуляция:** синхронизация шагов симуляции

**Примеры:**
- Параллельная сортировка: все потоки должны завершить фазу разделения перед фазой слияния
- Игровой движок: все системы должны завершить обновление перед рендерингом
- Научные вычисления: синхронизация итераций в параллельных алгоритмах

## 🏗️ Архитектура

```
Горутина 1: [Работа] → [Барьер] → [Ждёт] → [Все продолжают]
Горутина 2: [Работа] → [Барьер] → [Ждёт] → [Все продолжают]
Горутина 3: [Работа] → [Барьер] → [Ждёт] → [Все продолжают]
                    ↑
              Все встречаются здесь
```

**Важно:** Барьер работает в раундах. После того, как все горутины прошли барьер, он сбрасывается для следующего раунда.

## ⚙️ Реализация

### Базовая реализация через канал

```go
type Barrier struct {
    mutex    sync.Mutex
    count    int              // Количество горутин, достигших барьера
    size     int              // Общее количество горутин
    waitCh   chan struct{}    // Канал для ожидания
    round    int              // Номер раунда
}

func NewBarrier(size int) *Barrier {
    return &Barrier{
        size:   size,
        waitCh: make(chan struct{}), // Небуферизованный канал
    }
}

func (b *Barrier) Wait() {
    b.mutex.Lock()
    b.count++

    // Если это последняя горутина
    if b.count == b.size {
        // Закрываем канал, чтобы разбудить всех ожидающих
        close(b.waitCh)
        // Создаём новый канал для следующего раунда
        b.waitCh = make(chan struct{})
        b.count = 0
        b.round++
        b.mutex.Unlock()
        return // Последняя горутина не ждёт
    }

    // Сохраняем ссылку на канал
    waitCh := b.waitCh
    b.mutex.Unlock()

    // Ждём, пока последняя горутина не закроет канал
    <-waitCh
}
```

**Как это работает:**
1. Каждая горутина вызывает `Wait()` и увеличивает `count`
2. Когда `count == size`, последняя горутина закрывает канал
3. Все ожидающие горутины получают сигнал (чтение из закрытого канала не блокируется)
4. Барьер сбрасывается для следующего раунда

### Использование

```go
barrier := NewBarrier(3) // 3 горутины должны встретиться

for i := 0; i < 3; i++ {
    go func(id int) {
        // Фаза 1: работа
        doWork(id)
        
        // Барьер: ждём всех
        barrier.Wait()
        
        // Фаза 2: все продолжают одновременно
        doMoreWork(id)
    }(i)
}
```

## 🔄 Barrier vs WaitGroup

| Аспект | Barrier | WaitGroup |
|--------|---------|-----------|
| **Назначение** | Синхронизация в точке встречи | Ожидание завершения работы |
| **Повторное использование** | Да (раунды) | Нет (одноразовый) |
| **Когда использовать** | Синхронизация фаз | Ожидание завершения горутин |
| **Поведение** | Все ждут, затем все продолжают | Главная горутина ждёт остальных |

**Пример:**
```go
// WaitGroup: главная горутина ждёт воркеров
var wg sync.WaitGroup
wg.Add(3)
for i := 0; i < 3; i++ {
    go func() {
        defer wg.Done()
        work()
    }()
}
wg.Wait() // Главная горутина ждёт

// Barrier: воркеры ждут друг друга
barrier := NewBarrier(3)
for i := 0; i < 3; i++ {
    go func() {
        work1()
        barrier.Wait() // Все ждут друг друга
        work2()       // Все продолжают одновременно
    }()
}
```

## 🔄 Barrier vs Semaphore

| Аспект | Barrier | Semaphore |
|--------|---------|-----------|
| **Назначение** | Синхронизация встречи | Ограничение доступа |
| **Поведение** | Все ждут, все продолжают | Ограничение количества |
| **Когда использовать** | Синхронизация фаз | Ограничение ресурсов |

**Пример:**
```go
// Barrier: все должны встретиться
barrier.Wait() // Все 3 горутины ждут друг друга

// Semaphore: ограничение доступа
semaphore.Acquire() // Максимум 3 горутины могут работать
```

## ⚠️ Ловушки

### 1. Неправильное количество горутин

**Проблема:** Если количество горутин не совпадает с `size` барьера, барьер никогда не откроется.

```go
// ПЛОХО: 4 горутины, но барьер на 3
barrier := NewBarrier(3)
for i := 0; i < 4; i++ {
    go func() {
        barrier.Wait() // 4-я горутина будет ждать вечно
    }()
}

// ХОРОШО: количество совпадает
barrier := NewBarrier(4)
for i := 0; i < 4; i++ {
    go func() {
        barrier.Wait()
    }()
}
```

### 2. Забытый вызов Wait()

**Проблема:** Если одна горутина не вызвала `Wait()`, остальные будут ждать вечно.

**Решение:** Всегда вызывать `Wait()` в каждой горутине, которая должна синхронизироваться.

```go
// ПЛОХО: одна горутина забыла вызвать Wait()
for i := 0; i < 3; i++ {
    go func(id int) {
        if id != 2 {
            barrier.Wait() // Горутина 2 не вызвала Wait()
        }
    }(i)
}

// ХОРОШО: все вызывают Wait()
for i := 0; i < 3; i++ {
    go func(id int) {
        barrier.Wait() // Все вызывают
    }(i)
}
```

### 3. Повторное использование без сброса

**Проблема:** Если барьер не сбрасывается между раундами, второй раунд не сработает.

**Решение:** Барьер должен автоматически сбрасываться после каждого раунда (как в нашей реализации).

```go
// Наша реализация автоматически сбрасывает барьер
barrier.Wait() // Раунд 1
barrier.Wait() // Раунд 2 (автоматически сброшен)
```

### 4. Race condition при чтении канала

**Проблема:** Если несколько горутин читают из одного канала одновременно, может быть race condition.

**Решение:** Сохранять ссылку на канал перед чтением (как в нашей реализации).

```go
// ХОРОШО: сохраняем ссылку на канал
waitCh := b.waitCh
b.mutex.Unlock()
<-waitCh // Читаем из сохранённой ссылки
```

### 5. Закрытие канала несколько раз

**Проблема:** Если попытаться закрыть канал дважды, произойдёт паника.

**Решение:** Закрывать канал только один раз (когда `count == size`).

```go
// В нашей реализации канал закрывается только один раз
if b.count == b.size {
    close(b.waitCh) // Закрываем только здесь
    b.waitCh = make(chan struct{}) // Создаём новый для следующего раунда
}
```

## 💡 Вопросы для размышления

1. **Почему используется небуферизованный канал?** (Чтобы гарантировать, что все горутины заблокируются до закрытия канала)
2. **Что произойдёт, если использовать буферизованный канал?** (Горутины могут не дождаться друг друга)
3. **Почему последняя горутина не ждёт?** (Она закрывает канал и сразу продолжает, остальные уже ждут)
4. **Можно ли использовать Barrier для синхронизации разных фаз?** (Да, вызывать `Wait()` между фазами)
5. **В чём разница между Barrier и `sync.WaitGroup`?** (Barrier — воркеры ждут друг друга. WaitGroup — главная горутина ждёт воркеров)

## 🔧 Практические примеры

### Пример 1: Синхронизация фаз обработки

```go
barrier := NewBarrier(3)

for i := 0; i < 3; i++ {
    go func(workerID int) {
        // Фаза 1: загрузка данных
        data := loadData(workerID)
        barrier.Wait() // Ждём всех
        
        // Фаза 2: обработка данных (все начинают одновременно)
        result := processData(data)
        barrier.Wait() // Ждём всех
        
        // Фаза 3: сохранение результатов
        saveResult(result)
    }(i)
}
```

### Пример 2: Параллельная сортировка

```go
barrier := NewBarrier(4) // 4 потока

for i := 0; i < 4; i++ {
    go func(threadID int) {
        // Фаза 1: разделение данных
        partition := partitionData(threadID)
        barrier.Wait()
        
        // Фаза 2: сортировка (все начинают одновременно)
        sortPartition(partition)
        barrier.Wait()
        
        // Фаза 3: слияние
        mergeResults(partition)
    }(i)
}
```

### Пример 4: Научные вычисления (итерации)

```go
barrier := NewBarrier(8) // 8 потоков

for i := 0; i < 8; i++ {
    go func(threadID int) {
        for iteration := 0; iteration < 100; iteration++ {
            // Вычисления на итерации
            compute(threadID, iteration)

```

### Пример 5: Координация воркеров

```go
barrier := NewBarrier(5) // 5 воркеров

for i := 0; i < 5; i++ {
    go func(workerID int) {
        for task := range taskQueue {
            // Обработка задачи
            processTask(task)
            
            // Синхронизация: все должны завершить задачу
            barrier.Wait()
            
            // Все продолжают одновременно

        }
    }(i)
}
```

## 🎯 Преимущества Barrier

1. **Синхронизация фаз:** все горутины синхронизируются в одной точке
2. **Координация:** можно координировать выполнение разных фаз
3. **Повторное использование:** барьер можно использовать многократно
4. **Простота:** простая реализация через канал

## 🔄 Barrier vs Другие примитивы

| Примитив | Назначение | Когда использовать |
|----------|-----------|-------------------|
| **Barrier** | Синхронизация встречи | Все должны встретиться в точке |
| **WaitGroup** | Ожидание завершения | Главная горутина ждёт воркеров |
| **Semaphore** | Ограничение доступа | Ограничение количества одновременных доступов |
| **Mutex** | Взаимное исключение | Только 1 горутина в критической секции |

## 🔧 Альтернативная реализация (с cond)

```go
type Barrier struct {
    mutex sync.Mutex
    cond  *sync.Cond
    count int
    size  int
}

func NewBarrier(size int) *Barrier {
    b := &Barrier{size: size}
    b.cond = sync.NewCond(&b.mutex)
    return b
}

func (b *Barrier) Wait() {
    b.mutex.Lock()
    b.count++
    
    if b.count < b.size {
        b.cond.Wait() // Ждём, пока все не придут
    } else {
        b.count = 0
        b.cond.Broadcast() // Будим всех
    }
    
    b.mutex.Unlock()
}
```

**Сравнение:**
- **Канал:** проще понять, но нужно создавать новый канал для каждого раунда
- **Cond:** сложнее, но не нужно создавать новые каналы
