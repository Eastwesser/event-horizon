# Tee: Инсайты от Мусаси

## 🔑 Суть паттерна

**Tee (разветвитель)** — дублирование потока данных во все выходные каналы одновременно.

**Принцип:** Один канал → все каналы (каждое значение идёт во все каналы)

**Аналогия:** Команда Unix `tee` — выводит данные и в stdout, и в файл одновременно.

## 📊 Когда использовать?

- **Репликация данных:** один поток → несколько БД (каждая реплика получает все данные)
- **Логирование + метрики:** один поток → логи + метрики + мониторинг
- **Бродкаст:** одно сообщение → все подписчики
- **Множественная обработка:** один поток → обработка + сохранение + отправка

## 🏗️ Архитектура

```
Один канал ──> Tee ──┬──> Канал 1 (все данные)
                     ├──> Канал 2 (все данные)
                     └──> Канал 3 (все данные)
```

**Важно:** Все каналы получают **все** данные (в отличие от Fan-Out, где данные распределяются).

## ⚙️ Реализация

### Базовый вариант (блокирующий)

```go
for value := range inputCh {
    for i := 0; i < n; i++ {
        outputChs[i] <- value  // Блокируется, если канал полон!
    }
}
```

**Проблема:** Если один канал не читается (полон или нет читателя), вся горутина блокируется.

### Решение: select-default (неблокирующий)

```go
for value := range inputCh {
    for i := 0; i < n; i++ {
        select {
        case outputChs[i] <- value:
            // Записали успешно
        default:
            // Канал полон — пропускаем для этого канала
        }
    }
}
```

**Преимущества:**
- Не блокирует всю горутину
- Остальные каналы продолжают получать данные
- Защита от зависания

**Недостатки:**
- Данные могут теряться для перегруженного канала
- Нужно решить: что делать с потерянными данными?

## 🔄 Tee vs Fan-Out

| Аспект | Tee | Fan-Out |
|--------|-----|---------|
| **Распределение** | Все каналы получают все данные | Каждый канал получает часть данных |
| **Использование** | Репликация, логирование, бродкаст | Балансировка нагрузки, шардирование |
| **Пример** | Одно сообщение → все подписчики | 100 задач → 5 воркеров (по 20) |

## ⚠️ Ловушки

### 1. Блокирующая запись

**Проблема:**
```go
outputChs[i] <- value  // Если канал полон → блокировка всей горутины
```

**Решение:**
- `select-default` для неблокирующей записи
- Или буферизованные каналы (`make(chan T, bufferSize)`)

### 2. Потеря данных

**Вопрос:** Что делать, если канал полон?

**Варианты:**
1. **Пропустить (drop)** — данные теряются
2. **Буфер** — накапливать данные (риск переполнения памяти)
3. **Блокировка** — ждать, пока канал освободится (риск зависания)

**Выбор зависит от требований:**
- Логирование: можно пропустить (не критично)
- Репликация БД: лучше блокировать или использовать буфер

### 3. Закрытие каналов

- Закрываем все выходные каналы после завершения входного
- Это сигнал читателям, что данных больше не будет

## 💡 select-default: Глубокое понимание

### Как работает select?

```go
select {
case ch <- value:
    // Запись успешна (канал готов принять)
case <-time.After(1 * time.Second):
    // Таймаут
default:
    // Ни один case не готов — выполняется немедленно (неблокирующий)
}
```

**Правила:**
1. Если хотя бы один `case` готов → выбирается случайный готовый
2. Если ни один не готов и есть `default` → выполняется `default` (неблокирующий)
3. Если ни один не готов и нет `default` → блокируется до готовности

### Когда использовать default?

- **Неблокирующие операции:** не хотим ждать
- **Graceful degradation:** если операция не удалась, продолжаем работу
- **Защита от блокировок:** не хотим зависнуть

### Альтернативы select-default

1. **Буферизованные каналы:**
   ```go
   ch := make(chan T, 100)  // Буфер на 100 элементов
   ```
   - Защищает от блокировки, пока буфер не полон
   - Но может накапливать данные в памяти

2. **Контекст с таймаутом:**
   ```go
   select {
   case ch <- value:
   case <-ctx.Done():
       // Отмена операции
   }
   ```

## 🎯 Связь с другими паттернами

- **Fan-Out** — противоположность (распределение, а не дублирование)
- **Pipeline** — можно комбинировать: Tee → обработка → Fan-In
- **Broadcast** — Tee — это и есть бродкаст на уровне каналов
