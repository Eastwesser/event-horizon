# AUTH_HASHES_ISSUE_#1: Почему пароль Раисы перестал работать

**Дата:** 07.11.2026
**Статус:** Закрыт (сброс пароля через БД)
**Влияние:** Пользователь `raisa.matveeva@event-horizon.com` не мог залогиниться.

## Симптомы
- Логин возвращал `401 Unauthorized` с `{"error":"invalid credentials"}`.
- Пользователь существовал в БД, `nickname: "Raya ^w^"`, аккаунт не удалялся.
- Хеш пароля в БД был валидным bcrypt (`$2a$12$...`).

## Причина
При попытке сброса пароля использовался `htpasswd`, который генерирует хеши с префиксом **`$2y$`** (формат Apache/PHP).

Бэкенд Auth написан на Go и использует библиотеку `golang.org/x/crypto/bcrypt`. Эта библиотека **поддерживает только `$2a$` и `$2b$`**, а `$2y$` считает невалидным. Поэтому даже с правильным паролем `bcrypt.CompareHashAndPassword` возвращал ошибку, и Auth отдавал `401`.

**Почему пароль «потерялся»:** 
Скорее всего, при регистрации Раисы вчера использовался другой хеш (или другой пароль). Но когда мы попытались его сбросить через `htpasswd`, мы записали `$2y$`-хеш. Go его не понял, и логин продолжил падать.

## Решение
Сгенерировать хеш с префиксом `$2a$` через Python (библиотека `bcrypt`):
```bash
python3 -c "import bcrypt; print(bcrypt.hashpw(b'R@i\$04ka', bcrypt.gensalt(rounds=12, prefix=b'2a')).decode())"

Затем обновить запись в БД, экранируя символы $ в SQL (иначе Postgres попытается интерпретировать их как переменные):

bash

docker exec -it event-horizon-postgres psql -U eventhorizon -d eventhorizon -c \
  "UPDATE users SET password_hash = E'\$2a\$12\$...' WHERE email = '...';"

После этого логин заработал (200 OK).

Выводы на будущее

Никогда не использовать htpasswd для генерации хешей для Go-бэкенда. 
Использовать python3 -c "import bcrypt..." или go run с bcrypt.GenerateFromPassword.

В SQL всегда экранировать $ при работе с bcrypt-хешами (использовать E'...' или \$).

Добавить в скрипт seed_admin.py возможность сброса пароля по email (сейчас он игнорирует SEED_EMAIL и создаёт player@...). Это отдельная задача (BUG-).

В Auth можно добавить bcrypt fallback: если хеш начинается с $2y$, попробовать заменить префикс на $2a$ перед сравнением (костыль, но спасёт от таких инцидентов).
