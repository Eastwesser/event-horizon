🔌 6. WEBSOCKET И REAL-TIME

❓ Как работает WebSocket и чем отличается от SSE?
Ответ: WebSocket — это протокол, который устанавливает постоянное двунаправленное соединение. SSE (Server-Sent Events) — только от сервера к клиенту.

Характеристика	WebSocket	SSE
Направление	Двунаправленный	Только от сервера
Протокол	ws:// / wss://	HTTP (EventSource)
Заголовки	Свои	HTTP заголовки
Переподключение	Ручное	Автоматическое
Бинарные данные	✅	❌ (только текст)
В Event Horizon я использую WebSocket, потому что лидерборд должен получать обновления в реальном времени и клиент может отправлять команды.





❓ Как держать 10 000 WebSocket-соединений? Что такое Netpoll?
Ответ: В Go мы используем Netpoll — это механизм, который позволяет обрабатывать тысячи соединений на одном потоке, используя epoll (Linux) или kqueue (BSD).

Как это работает:

Один поток (goroutine) слушает все соединения

При появлении данных — пробуждает горутину

Нет 1 горутина = 1 соединение

В Event Horizon: Gateway использует Hub, который управляет всеми WebSocket-соединениями.

Код: services/gateway/internal/websocket/hub.go — Hub содержит карту клиентов.





❓ Как обновляешь лидерборд в реальном времени?
Ответ: Схема работы:

Game публикует событие score.updated в NATS

Leaderboard получает событие, обновляет Redis Sorted Set

Gateway получает событие через NATS и отправляет через WebSocket

Код: В Gateway есть NATS-подписка:

go
// Подписываемся на обновления лидерборда
js.Subscribe("score.updated", func(msg *nats.Msg) {
    var event ScoreEvent
    json.Unmarshal(msg.Data, &event)
    
    // Отправляем всем WebSocket-клиентам
    hub.Broadcast(event)
})
Hub отправляет всем клиентам:

go
func (h *Hub) Broadcast(message []byte) {
    h.mu.Lock()
    defer h.mu.Unlock()
    
    for _, client := range h.clients {
        client.Send(message)
    }
}





❓ Что если соединение оборвалось?
Ответ: В коде есть обработка:

go
func (c *Client) ReadPump() {
    for {
        _, message, err := c.Conn.ReadMessage()
        if err != nil {
            // Оборвалось — чистим
            c.Hub.Unregister <- c
            return
        }
        // Обработка сообщения
    }
}
Как я обрабатываю переподключение:

Клиент переподключается с тем же user_id

Сервер отправляет текущий топ лидерборда

Клиент получает полную историю



❓ Как ограничиваешь количество WebSocket-соединений?
Ответ:

На уровне сервера: MaxConnections в конфиге Gateway

На уровне системы: ulimit -n 65535

Rate Limiter: ограничиваем новые соединения от одного IP

Если слишком много:

Смотрим, какие комнаты перегружены

Добавляем новые экземпляры Gateway (горизонтальное масштабирование)

Включаем ограничение на количество соединений от одного пользователя

В Event Horizon: В Gateway нет жесткого лимита, но есть мониторинг через Prometheus.


🎯 КЛЮЧЕВЫЕ ТЕЗИСЫ ДЛЯ СОБЕСА
WebSocket vs SSE — WebSocket двунаправленный, SSE — только от сервера

Netpoll — обрабатывает тысячи соединений на одном потоке

Hub + NATS — получает событие и рассылает всем клиентам

Переподключение — клиент получает полный топ при восстановлении
