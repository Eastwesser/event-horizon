# HTTP status codes — шпаргалка senior (фокус на спорных)

## Быстрая карта

| Код | Смысл | Типичный EH-кейс |
|-----|-------|------------------|
| 200/201 | Успех / создано | GET list, POST create |
| 204 | Успех без тела | DELETE |
| 400 | Невалидный запрос | validate.rules, bad JSON |
| 401 | Не аутентифицирован | нет/битый JWT |
| 403 | Аутентифицирован, но нельзя | роль `user` на admin-route |
| 404 | Ресурса нет | item id не найден |
| 409 | Конфликт состояния | version mismatch, duplicate |
| 429 | Слишком много запросов | rate limit |
| 503 | Сервис недоступен | **circuit open**, dependency down |

## 401 vs 403 (обязательный вопрос)

- **401 Unauthorized** — «не знаем кто ты»: нет `Authorization`, истекший/поддельный JWT, сессия убита в Redis. Часто `WWW-Authenticate`.
- **403 Forbidden** — «знаем кто ты, но роль/политика запрещает»: `user` лезет в author/admin API.

Антипаттерн: отдавать 401 на «не твоя роль» — путает клиент (будет релогиниться вместо UX «нет прав»). В EH: Gateway `RequireAuth` → 401; `RequireRole` → 403; gRPC metadata `x-user-role`.

## 409 Conflict

Состояние ресурса не совместимо с запросом:
- Optimistic locking: `version` устарел.
- Уникальный email/username при регистрации.
- Повторное подтверждение платежа в неверном статусе (если не идемпотентный replay).

Клиенту: понятное тело (`resource_version_conflict`) + актуальная версия/etag, чтобы повторить с refresh.

## 429 Too Many Requests

Квоты: per-IP, per-user, per-token. Заголовки `Retry-After`. Не путать с 503: 429 — «ты пришёл слишком часто»; 503 — «мы/dependency лежим или отрезаны».

## 503 и circuit breaker

В EH Gateway circuit на billing/shop/payment: при **open** — fail-fast **503**, без ожидания полного gRPC deadline. Это защита каскадного отказа.

Отличия:
- 502 — плохой ответ upstream (редко путают).
- 504 — таймаут шлюза.
- 503 — временно недоступно / намеренный open.

`/ready` failing при недоступной БД — оркестратор не шлёт трафик; это не то же самое, что 503 на бизнес-методе, но родственник.

## gRPC ↔ HTTP (кратко)

На gateway маппинг: `InvalidArgument`→400, `Unauthenticated`→401, `PermissionDenied`→403, `NotFound`→404, `AlreadyExists`/`Aborted`→409, `ResourceExhausted`→429, `Unavailable`→503.

## Практические правила

- Не маскируйте 500 под 400 «на всякий случай».
- Тело ошибки: машинный `code` + человекочитаемый `message`, без стека в прод.
- Идемпотентный повтор с тем же ключом → тот же код успеха, не 409 «уже было» (если семантика ключа — replay ответа).
