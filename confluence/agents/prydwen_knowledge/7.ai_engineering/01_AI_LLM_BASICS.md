# LLM basics — шпаргалка senior (для backend / red_mad_robot)

## Модель в одном абзаце

LLM предсказывает следующий токен по контексту. Это **не** база знаний и **не** калькулятор с гарантиями. Полезность = хорошие промпты + внешние факты (RAG/tools) + проверка человеком/тестами на критичных путях.

## Токены

- Текст режется на токены (~0.6–0.8 слова для EN; для RU часто больше токенов на символ).
- Биллинг и лимиты — в токенах (input + output).
- Длинный системный промпт + история чата съедают бюджет до ответа.
- Сжатие: короткие инструкции, выкидывать нерелевантную историю, суммаризация.

Практический навык: оценить, влезет ли лог/OpenAPI в окно, или нужен RAG/chunk.

## Контекстное окно

Максимум токенов, которые модель «видит» за один запрос (system + messages + tool results). Всё за окном — невидимо. Следствия:
- Нельзя «скормить весь монорепо» одним промптом.
- RAG и MCP tools — способ подтянуть *релевантный* кусок.
- Порядок важен: инструкции и факты ближе к вопросу часто влияют сильнее (зависит от модели).

## Температура и детерминизм

- Низкая (0–0.2): код, JSON, классификация — меньше фантазий.
- Выше: мозговой штурм, тексты.
- Для прод-агентов: низкая температура + structured output + валидация схемы.

## Галлюцинации

Модель уверенно выдумывает API, порты, «уже существующие» таблицы. Митигация:
1. Давать источник истины (Prydwen, OpenAPI, `postgres_query`).
2. Требовать цитировать путь файла / subject NATS.
3. Запрещать додумывать секреты и прод-цифры.
4. Для EH: сверять порты с `03_PROJECT_EVENT_HORIZON.md`, не с памятью чата.

Признак риска: ответ про инфраструктуру без retrieval — высокая вероятность вымысла.

## Промптинг (минимум senior)

- Роль + задача + ограничения + формат выхода.
- Few-shot для стабильного JSON.
- «Не знаешь — скажи не знаю» снижает уверенный бред.
- Tool-calling: модель выбирает инструмент; вы контролируете allowlist и side effects.

## Когда LLM **не** использовать

| Задача | Почему лучше без LLM |
|--------|----------------------|
| Авторизация, RBAC, подпись JWT | Нужна криптографическая проверка |
| Идемпотентность платежа / outbox commit | Строгая транзакционная семантика |
| Точный SQL DDL в проде | Риск деструктивных команд |
| Rate limit / circuit open | Детерминированный код |
| Парсинг известной схемы protobuf | Кодоген + Validate() |
| Сортировка/фильтр в БД | Индексы и SQL, не «умный» текст |

LLM уместен: черновики, поиск по доке, объяснение логов, генерация тестов, code review assist — с человеком в контуре.

## Связь с Event Horizon

Агенты Cursor + MCP читают Prydwen и live infra. LLM не заменяет Gateway RBAC и bcrypt 12 — только помогает инженеру быстрее найти «как устроен Outbox в Shop».
