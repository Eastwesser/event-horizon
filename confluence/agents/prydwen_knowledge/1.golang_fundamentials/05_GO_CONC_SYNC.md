# Go: sync-примитивы

Когда каналов мало: разделяемое состояние, однократная инициализация, пулы объектов. Знать API и **когда не использовать**.

## Mutex

- `sync.Mutex`: `Lock` / `Unlock`. Нереентерабельный — повторный Lock той же горутиной = deadlock.
- Держите критическую секцию короткой: без I/O, без вызова чужого кода под локом (lock inversion).
- Паттерн: `mu.Lock(); defer mu.Unlock()` — даже при early return. Исключение: нужно Unlock до медленной операции — тогда явные границы.

**Питфол:** копирование struct с Mutex — копируется и состояние лока; всегда передавайте `*T` с mutex внутри.

## RWMutex

- Много читателей **или** один писатель.
- `RLock` дешевле при read-heavy, но писатели могут голодать при постоянных читателях.
- Не повышайте `RLock` → `Lock` в той же горутине (deadlock).
- Если write-доля высокая — обычный Mutex часто быстрее (меньше overhead).

## WaitGroup

- `Add(n)` **до** старта горутин (или синхронно там, где нет гонки с `Wait`).
- Каждая горутина: `defer wg.Done()`.
- `Add` отрицательным — ok (как Done×k), но `Add` после того как counter мог достичь 0 и `Wait` вернулся — race/panic.
- Go 1.20+: `wg.Go(func(){ ... })` — меньше ошибок с Add/Done.

**EH:** shutdown нескольких workers — WaitGroup + cancel context; не `time.Sleep("достаточно")`.

## Once

- `sync.Once` — `Do(f)` выполнит `f` ровно один раз на процесс/экземпляр Once.
- Для lazy init singleton (logger, metrics register).
- Если `f` паникует — считается выполненным; повторно не вызовется. Ошибки инициализации проектируйте явно (atomic + error), не только Once.

## Pool (`sync.Pool`)

- Кэш временных объектов между горутинами; **может быть очищен GC** в любой момент — не для важных данных.
- Типично: буферы `[]byte`, `bytes.Buffer` в hot path JSON/proto.
- `Get` может вернуть nil-инициализацию — всегда type assert + reset длины/состояния.
- Не кладите в Pool объекты с «грязным» PII без очистки.

## atomic

- Пакет `sync/atomic`: `AddInt64`, `Load/Store`, `CompareAndSwap`, `atomic.Pointer[T]` (Go 1.19+), `atomic.Bool` и т.д.
- Для счётчиков метрик, флагов shutdown, generation number.
- Не заменяет Mutex для составных инвариантов («проверил-потом-записал» два поля) — нужен CAS-цикл или лок.
- Alignment: на 32-bit `int64` atomic требует выравнивания; на amd64 обычно ок в начале struct.

## Cond (редко)

- `sync.Cond` — wait/signal на сложном условии. Легко ошибиться; чаще достаточно channel. На собесе достаточно сказать «предпочитаю channel/context».

## Карта выбора

| Задача | Инструмент |
|--------|------------|
| Счётчик / флаг | atomic |
| Защита map/struct | Mutex / RWMutex |
| Дождаться N задач | WaitGroup |
| Init один раз | Once |
| Переиспользование буферов | Pool |
| Передача владения | channel |
