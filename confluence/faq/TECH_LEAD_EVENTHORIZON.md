## 🛠 Технические компетенции

### Профилирование и оптимизация производительности
- Инструменты: `pprof` (CPU, memory, goroutines) + Grafana (визуализация)
- Методы: профилирование воркеров, поиск утечек горутин, оптимизация блокировок
- Практика в EventHorizon:
  - Нагрузка: 10k RPS (заявлено и протестировано)
  - WebSocket: real-time leaderboard с broadcast через NATS
  - Prometheus + Grafana для мониторинга RPS, latency, ошибок
  - Jaeger для трейсинга (внедряется)

### Тестирование (покрытие 70–75% на бизнес-логике, 50–60% на инфраструктуре)
| Тип теста | Использование в EventHorizon |
|-----------|------------------------------|
| Unit-тесты | Бизнес-логика игр (валидация ходов, подсчёт очков) |
| E2E тесты | Outbox таблицы, проверка идемпотентности, интеграции с NATS |
| Mock-тесты | Базы данных, внешние API (gRPC клиенты) |

### Архитектура и инфраструктура
- Микросервисы на Go: **Auth, Game, Billing, Leaderboard, Gateway**
- Протоколы: gRPC (внутренние вызовы), HTTP/REST (фронтенд), WebSocket (лидерборд)
- Брокер сообщений: **NATS JetStream** (асинхронная обработка, события score.updated)
- Базы данных: **PostgreSQL** (ACID для Auth, Game, Billing, Leaderboard)
- Кэш: **Redis** (сессии, балансы, Sorted Set для топа)
- Нагрузка: 10k RPS, WebSocket real-time
- Мониторинг: **Prometheus + Grafana + Jaeger + Alertmanager**

## 📊 SLO / SLI / Error Budget (практический опыт в EventHorizon)

### Определение SLO
- Выделяли **ключевые бизнес-сценарии**:
  - Отправка рекорда (`POST /api/game/submit`)
  - Получение лидерборда (`GET /api/leaderboard`)
  - WebSocket обновления (`ws://.../ws/leaderboard`)
- SLO:
  - p95 latency для `/game/submit` < 500 мс
  - error rate < 1% для всех эндпоинтов
  - WebSocket задержка < 2 секунды

### SLI
- Считали через Prometheus:
  - Доля успешных запросов за последние 5 минут
  - `rate(gateway_requests_total{status=~"2.."}[5m]) / rate(gateway_requests_total[5m])`
- Алерты в Telegram при падении SLI ниже SLO

### Error Budget
- Бюджет: общее количество запросов за квартал × допустимый процент ошибок (1%)
- Если бюджет почти исчерпан — блокировали эксперименты и feature flags, даже если бизнес просил
- Приоритет: сначала стабильность, потом фичи
- В EventHorizon: ошибки **5xx** отслеживаются через алерты в Grafana

## 🔗 EventHorizon — полный стек для собеседования

### Микросервисы
| Сервис | Назначение | Порт |
|--------|------------|------|
| Auth | JWT, регистрация, логин | 50051 |
| Game | Валидация ходов, подсчёт очков | 50052 |
| Billing | Лампочки, билетики, транзакции | 50053 |
| Leaderboard | Топ игроков (Redis Sorted Set) | 50054 |
| Gateway | HTTP → gRPC прокси, WebSocket, rate limiter | 8080 |

### Коммуникация
- **Синхронная:** gRPC между сервисами
- **Асинхронная:** NATS JetStream (события `score.updated`)
- **Реал-тайм:** WebSocket (broadcast лидерборда)

### Базы данных
- **PostgreSQL:** Auth (пользователи), Game (рекорды), Billing (транзакции), Leaderboard (бэкап)
- **Redis:** Сессии (6379), игровой кэш (6380), биллинг (6381), лидерборд (6382)

### Мониторинг
| Инструмент | Назначение | Порт |
|------------|------------|------|
| Prometheus | Сбор метрик | 9090 |
| Grafana | Дашборды | 3000 |
| Jaeger | Трейсинг | 16686 |
| Alertmanager | Алерты в Telegram | — |

### Бизнес-метрики
- `gateway_requests_total` — RPS по эндпоинтам
- `gateway_request_duration_seconds` — Latency (P50/P95/P99)
- `game_submits_total` — Количество игр по типам
- `game_score_histogram` — Распределение очков

### Нагрузка
- Целевая: 10k RPS
- WebSocket: real-time обновления
- Протестировано: 10k WebSocket, 4k HTTP
